- Rework (gate 08): root cause — `SentenceList.tsx` scrolled the active sentence card with `element.scrollIntoView({ block: 'nearest' })`, which per CSSOM scrolls every scrollable ancestor; the card (expanded, taller than its own 276px inner viewport) always overflowed, so the shell's main scroll viewport was dragged ~330px down on editor mount and the pending mark-proposal banners at the top of `.editor-workbench` left the viewport (ratio 0, deterministic). Neither `container-type` nor the AppShell scroll-reset was involved. Fix: nearest-edge alignment constrained to the card's own `[data-scroll-viewport]` in `SentenceList.tsx` — same semantics as `block: 'nearest'` (fully visible or fully covering → no scroll; partial overflow → minimal edge alignment) but never propagating to shell ancestors. Spec migrations in `tests/e2e/m1b-gate.spec.ts` (no assertions deleted/weakened): (1) 文本标记 `<select>`/`option` assertions migrated to open the advanced-mode `Dropdown` and assert `menuitem` presence/absence in the menu (dusk-glow absent before accept, present after; boat-trail absent after reject); (2) `toBeInViewport` banner assertions ordered before any mouse interaction, since Playwright auto-scrolls clicked controls into view and asserting mount-time visibility is the actual semantic; (3) `章节运行记录` assertion re-scoped from the chapter listitem to the page, since run records now render in a `Drawer` (task 04 surface).
