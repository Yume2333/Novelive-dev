### Rework round 4 (1c)

- Rework base commit: 772e8dc68aceea2509123f4037ff18098ff3d52e
- Fix: two lines in `packages/ui/src/components/Form.module.css` — `width: 100%` on `.compactSelect` and `width: fit-content` on `.compactSelectShell`. Previously a sized shell (e.g. settings `span.rowSelect { min-width: 150px }`) stretched while the inner `<select>` kept intrinsic width, so the absolutely positioned chevron floated outside the visible box (settings 界面 section: box x1061–1156, chevron x1194). `width: 100%` makes the select fill a sized shell so the chevron lands inside the box. `width: fit-content` on the shell is required because the shell is a flex/grid item in several consumers (`Field` is `display: flex; flex-direction: column`; settings model grid, editor `editor-sentence-meta` grid) where `align-items: stretch` would otherwise stretch the shell — and with it the select — to the full column width, regressing the prototype's compact sizing; `fit-content` keeps unsized shells collapsed to the select's intrinsic width while consumers that set an explicit width or `min-width` (`rowSelect`) still override it and size the whole control. Audited every `CompactSelect` consumer: usage filter row + granularity picker, editor chapter/scene/expression/mark pickers, SceneImages/SentenceList `Field` columns, bible volume switcher, production role-model rows, settings `ModelFields` (compat/format/quality/nativeMaxEdge/postProcess/upscaleTier) and production role rows — only `rowSelect` passes a sizing class. Empirical probe (below) confirms: sized shells fill to 150px with the chevron inside; every unsized consumer's shell == select == intrinsic width (no stretch).
