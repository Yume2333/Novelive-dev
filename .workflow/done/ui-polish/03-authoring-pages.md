- **Freeze root cause (issue A): NOT a React/ScrollArea render loop.** Bisect with an instrumented bundle showed: ProductionPage renders exactly once, no render storm, no IPC call storm, React work-loop never blows up — yet the renderer AND the Electron main process both block hard. The actual root cause is in `tests/fixtures/creation-ui/projection.ts`: `installProjection`'s `app.evaluate` function is serialized and run in the Electron main process, but its `usage.list` case referenced the module-level const `workId` (projection.ts:9), which is not in scope inside the serialized function. The first `usage.list` roundtrip therefore threw a ReferenceError in the main process — an uncaught exception that hangs the main process (Electron blocking error dialog) and with it the renderer waiting on the bridge. This matches every bisect observation: static injection of the same entries never froze (no usage.list roundtrip), sending usage.list without ever resolving the promise still froze (the throw happens in the main-process handler, before/independent of the renderer resolution), and swallowing the call entirely stayed alive. Fix: pass `workId` through the fixture object argument (`fixture.workId`) — the fixture itself was broken, not ProductionPage or ScrollArea. No production code needed changing for the freeze; `packages/ui/src/components/ScrollArea.tsx` is untouched, and an experimental `usePresence` change was reverted after evidence showed it did not affect the freeze. A full scan of the evaluate body found no other out-of-scope runtime identifiers (remaining matches are types or property access).
