# Authoring flow parity audit

Every pair is 1280 × 1000, light and dark. `*-prototype.jpg` comes from `prototype/` (Vite, mock data). `*-result.jpg` comes from the real Electron app (`NL_REPLAY=strict`): import uses the m1b-wizard TXT fixture; work, production and confirm use the m1b-creation-ui projection fixture.

| Page | Matches prototype | Residual differences (data/contract) |
| --- | --- | --- |
| Import · 选择文件 | `从原文开始` eyebrow, `新建工程` title at width 760, three-step stepper, side-by-side source / reference drop zones, file rows with tags, folder field and `放进哪里` radios beneath, `下一步` outside the card. | The prototype has no `作品名` field; the real flow keeps it because `import.file` needs a title. |
| Import · 核对信息 | Stepper on step 2, field grid, `分卷 · N 卷 M 章` label, one volume box per volume with indexed chapter rows and split/merge/start-volume actions. | The prototype has author, work-language and chapter-title inputs, which have no layout fields. The encoding/findings panel is real-data only. |
| Import · 改编设置 | Stepper on step 3, settings card, reference-image toggle (when references/illustrations exist) or ready-to-start notice, `上一步` and `开始制作` outside the card. Draft state carries over from step 2, and step 3 sends a single `import.revise`. | Adaptation strength, density and requirements have no contract fields, so only the reference toggle (when applicable) is shown. |
| Work overview | Title header with a `更多` menu (查看制作, 导出作品包) and `开始游玩` as the primary action. Hero card with cover, `{series} · 第 {index} 卷 · {volume}` hierarchy from `library.list`, title, publish count and expandable synopsis. Phase card. `章节目录 · 共 N 章` list with status pills and pagination. | The cover is a fallback icon because the snapshot has no cover art; the prototype also shows author and language fields that the contract does not carry. |
| Production | `{series} · 第 {index} 卷` eyebrow, `<作品> · 制作` title, `立即停止` with the danger-container style, current-chapter card with status chip and progress, `第 {index} 卷 · {volume} · 共 N 章` volume label from `library.list`, indexed rows with a step trail (写剧本 › 审稿 › 演出 › 出图), progress bar, `制作中`/`等待` pills and hover row actions. | There is no 全部重试 because no command exists for it. |
| Confirm visual | `{series} · 第 {index} 卷 · 确认点 1 / 2` eyebrow, `<作品> · 角色设定 / 主视觉` title with info tooltip, missing count, confirm action, main-visual gallery card, left character selector with the costume gallery on the right, supplemental references. | Regenerate and appearance editing have no command. The candidate art in the result is fixture placeholder colour. |
| Confirm first | `{series} · 第 {index} 卷 · 确认点 2 / 2` eyebrow, `<作品> · 第一章成品` title with info tooltip, `试玩第一章`, `更多` menu with a working `进编辑器修改` (opens the editor on that chapter) and `继续制作`, real per-scene cards in the prototype 3-column grid at content width 960: first `bg` art resolved through the player registry, `场景 N` badge, scene title, first narration line, and per-type image counts. | Scene descriptions show the first text line of each scene rather than a hand-written synopsis; scenes without a `bg` asset fall back to a token gradient. |

All captures are 1280 × 1000, light and dark, regenerated from the final integration code. Result images are produced by two Playwright tests in `tests/e2e/prototype-parity.spec.ts` (`authoring flow pages capture matched-viewport parity evidence` uses the `creation-ui` projection fixture; `import wizard pages capture matched-viewport parity evidence` uses the m1b-wizard TXT fixture and the real creator). The projection fixture now returns a `library.list` project entry and a two-scene `production.playerChapter` script so the hierarchy and scene cards render with real code paths.
