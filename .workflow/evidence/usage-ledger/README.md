### Discrepancies and deduplication

- **The private budget export is not the latest shared balance.** Its 338 data rows sum to 2,809,805 tokens and 4 images, including 242,766 tokens of open reserves. Every row matches the [M1a rollup](../m1a/owner/usage.csv) by date, model, purpose, counts and amounts (neither CSV has request IDs or times). Identical-looking HTTP 401 rows are two attempts, not duplicates. M4's first smoke is in both CSVs and the [receipt](../m4-longform/paid-smoke.txt); the full-artwork follow-up is in the M1a rollup and receipt, not the readable private export. Count each smoke once. The follow-up gives a combined 71,610 input / 29,906 output, not a per-model split. The first smoke's local budget rejection, offline playback and unused authorization add no relay calls.
- **The baseline gap predates the later M1b windows.** The deduplicated CSVs, including the distinct M4 follow-up, give 2,668,555 settled tokens / 11 images and 242,766 reserved tokens. The older shared comparison (historical `7664e1a:.workflow/owner-review.md:12-14`, 付费账本对账) was already higher by 46,088 settled tokens / 3 images and 33,306 reserved tokens. The [style receipt](../m1b/style/receipt.txt) separately documents 33,412 settled tokens across Gemini and Sunburst, including three Sunburst images, and a 100,000-token / one-image HTTP 404 reserve. No per-model token split is available. After adding style and the four production probes, the reported basis immediately before the first `27ef7dc` attempt is still higher than the evidence by **140,455 settled tokens / 12 images and 195,450 reserved tokens / 1 image**. Every subsequent shared delta matches its window; the earlier gap is carried, not treated as metered or released.
- **Two M1b receipts were recovered from a separate branch.** The [`27ef7dc` HTTP 404](../m1b/owner/live-run-27ef7dc.md) and the [distinct 149,959-token resume](../m1b/owner/live-resume-27ef7dc.md), with their usage CSVs, were copied unchanged from commit `d217e36` on `origin/devin/1795457450-m1b-owner-live`. The HTTP 404 reserve is included in its reported cumulative total and is not counted again in the resume. The later M1b CSVs and companion reports describe the same windows; use each window once, not the repeated project or shared cumulative totals. PR #68's M1a usage CSV and PR #83's artwork receipt agree with main; PR #69's handoff is a separate, older cross-session accounting summary, not an additive receipt.
- **A failed call is not necessarily free.** The two W4 HTTP 401s were released; the two M1b HTTP 404s retained their reserves. Three W4 timeouts and the final M1b HTTP 503 retained reserves under `transport_failure`. W4's possible interruption has one reserve but zero recorded calls; `b424d2e` has two reserves despite an application zero-usage record, and `03fcb97` has three in-flight reservations with no terminal usage. Local cutoffs and pre-dispatch budget denials are zero relay calls. HTTP 200 responses with provider usage stay settled even when JSON validation or an artwork check later fails. Loopback, synthetic replay and temporary/released authorization are excluded.
- **Some historical receipts cannot be linked to the current snapshot.** The older M1b real-book report (`a0fe816`, retained on `origin/m1b-production/11-m1b-owner-book`) is for a different book and lists 1,221,068 measured tokens / 25 images plus one cancelled 65,536-token / one-image reserve. Its last 20,360 settled tokens span Gemini and Sunburst without a split. This report alone exceeds the shared gap. The M0 image smoke (19,195 tokens / 3 images), M1b provider art smoke (75,554 tokens across models, nine **image requests**, not nine verified generated images) and M4 live spot checks (2,266 tokens / zero generated images) are also recorded as `overlap_unknown`. Their raw cross-session ledger is not available in this checkout. Older W4 receipt and handoff figures cannot be matched to the W4 CSV across runs; neither those summaries nor the unlinked receipts are added to the shared balance or used to release the gap.
- **Two new receipts are folded in once each.** The M1a/07 W4 owner-book window is recorded from the per-call [`w4-run-usage.csv`](../m1a/owner/w4-run-usage.csv) (241 measured calls / 2,269,588 tokens + 15 conservative reservations / 243,542 tokens = 256 calls / 2,513,130 tokens / 0 images). Its totals exactly match the six aggregate 2026-11-25 rows in the [M1a rollup](../m1a/owner/usage.csv) — they are the same window, counted once; the per-call file is the ledger source. The M1b/11 [`live-run-2026-11-24`](../m1b/owner/live-run-2026-11-24-usage.csv) window contributes three `unallocated` rows (w1/w2/w3) because the receipt publishes only per-window settled/unresolved totals, not a per-model split: 6,545,079 settled tokens / 266 images and 8,991,037 unresolved tokens / 210 image slots. The 210 unresolved image slots are abandoned reservations (`actual_* IS NULL`, no supplier usage), retained for audit — not verified consumption.

CSV paths are relative to `.workflow/evidence/`; a leading commit identifies a historical version. `budget` means the read-only `~/memory/poke_81b5d6/files/novelive-budget/ledger.csv`, with 1-based line numbers including the header. Sum `shared_evidence` for evidenced totals and add only `shared_unattributed` to reproduce the reported balance. `overlap_unknown` is retained for audit, not added. Blank means unavailable or represented on a joint row, not zero. Token splits cover only the indicated calls; when a receipt gives total and output for a call, input is their difference. A reserve appears on the same row as the rejection or transport failure that left it open, never on a second row.
