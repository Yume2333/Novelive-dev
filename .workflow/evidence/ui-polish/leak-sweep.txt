### R3. SettingsPage `readableError` `unsupported` passthrough of `failure?.message` (owner 02) — FIXED
Round-1 hardening note. SettingsPage.tsx:85-119 now reads:
```
export function readableError(error: unknown): ReadableError {
	const failure =
		error && typeof error === 'object' && 'code' in error
			? (error as CommandError)
			: undefined
	const code = failure?.code ?? 'internal'
	// 只有后端已本地化（或含 CJK）的 message 才能直接展示；
	// 英文原文等技术细节只能进折叠的「详细信息」。
	const readable =
		failure?.message &&
		('localized' in failure || /[\u3400-\u9fff]/.test(failure.message))
			? failure.message
			: undefined
	const detail =
		failure?.message && failure.message !== readable
			? failure.message
			: undefined
	const message = {
		...
		unsupported: readable ?? t('当前模型不支持此项。'),
		...
	}[code]
	return detail ? { code, message, detail } : { code, message }
}
```
The `unsupported` passthrough now goes through the same `readable` gate as `invalid_config`/`internal`: a raw message is
displayed only if the backend marked it `localized` or it contains CJK; otherwise the localized fallback sentence renders
and the raw English text is demoted to `detail`, rendered only inside `<Details>` (SettingsPage.tsx:313-318). VERIFIED FIXED.
