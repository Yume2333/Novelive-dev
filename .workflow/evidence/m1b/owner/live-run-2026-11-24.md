## 本次发现并修复的产品缺陷（真实代码，含离线回归测试）

1. **图片下载被 SSRF 守卫误杀** — `packages/creator/src/models/image/download.ts`：上游以 `url` 形式返回生图结果（`images/edit` 忽略 `response_format:'b64_json'`），CDN 与 relay 同处运营商非公网段。原 `publicAgent` 一律拒绝非公网地址 → 每个 url 型绘制必然占位。修复：按 `baseUrl` 建 undici `Agent`，仅当下载 IP 与**非公网** `baseUrl` 同网段（IPv4 /16、IPv6 前 4 组）时放行；外部私网（10.x 等）仍拒绝，SSRF 防护保留。
2. **dispatcher 在 replay 层被丢弃** — `packages/creator/src/replay/index.ts`：`replayFetch` 的 `dispatch` 用 `new Request(input, init)` 重建请求会丢掉 undici 非标 `init.dispatcher`，自定义下载 Agent 因此根本没上线路。修复：`sendLive` 显式把 `init.dispatcher` 透传给 `send`。
3. **回归测试** — `tests/unit/m0-image.test.ts` +2 严格离线用例（loopback 同网段 CDN 放行；10.x 外网仍拒），85/85 通过。

## 运行期产品观察（未改代码，记录供后续）

- `dispatchImages()`（scheduler/chapter）只在 `work.status ∈ {active, awaiting_confirm}` 时派发图片任务；四章全发布即 `done`，遗留 `queued` 图片任务不再被派发——需要把受影响章节重置回 `await_draw` + `work→queued` 才会补绘。
- `chapterImageBudget()` 用 `COALESCE(actual_images, images)` 计入**已放弃预留**（进程被杀、永不核销的 `actual_* IS NULL` 行），导致预算被大量无效预留占满而 `budget_paused`。
- `requeueRecoverablePlaceholders` 只自动匹配 sprite-frame/base-placeholder 文案；`error_type='placeholder'`/`budget_paused` 的任务需手动重置才会重试。

## 上游波动与最终阻塞

- 生图端点持续抖动：HTTP 503 `provider did not return a usable response`（99 次）、`图片服务暂时不可用`（137 次）、连接中断（133 次），另有质量审查拒绝（构图/画风/差分尺寸）。期间有少量绘制成功（55 张最终 `drawn`）。
- **最终硬阻塞**：直接探测 `POST /v1/images/generations` 返回 HTTP 503 `auth_unavailable: no auth available (… billing_error: insufficient balance)`——生图模型上游账户余额耗尽。文本端点（`deepseek-v4.1-flash`）同时段 HTTP 200 正常，证明仅为生图计费通道中断。**此为外部计余额，代码与重试均无法解决**；据此按有界重试原则停止补绘并如实上报。
