# Decisions

Append-only log of hard-to-reverse choices where a real alternative was rejected
(CONVENTIONS §1). Skip routine implementation details and choices already stated
in a spec, `standards.md`, or module contract. Git union-merges concurrent
additions, so entries may interleave out of date order; cite by
`decisions.md: <date> - <title>`.

## Format

Add `## <YYYY-MM-DD> - <title>` entries under `## Entries`. Every entry requires three
non-empty English field names (values may be in any language):

- **Decided:** what was chosen
- **Instead of:** the strongest alternative that lost
- **Because:** why it lost here

Optional: **Effort** (the `<slug>` the decision belongs to), **Decided by** (`user` or
`agent`; on parallel branches include the task ref, e.g. `agent (core/04)`, so
concurrent entries never share identical trailing lines under union merge),
**Revisit when** (condition that reopens the decision as a question for `flow-grill`,
and that `flow-architect` consults), and **Supersedes** (`<YYYY-MM-DD> - <old title>`;
leave the older entry untouched so the file stays strictly append-only).

User waivers of a `Check` or a review finding are recorded in the task file
(`Check waived` / `Review: waived`), not here.

```markdown
## 2026-01-31 - Retries capped at 3, no backoff

- **Decided:** three immediate retries, then fail.
- **Instead of:** exponential backoff with jitter.
- **Because:** the only caller retries within a single user request; a 30-second
  backoff would outlive the request it is serving.
- **Effort:** demo
- **Decided by:** user
- **Revisit when:** a background job starts calling this.
```

## 2026-11-23 - 共用文本输出预算和推理耗尽重试

- **Decided:** 使用模型目录的输出上限和各槽位可选的真实输出上限；无目录或设置时，仅按上下文估算安全预算，不将估算冒充供应商上限。不默认发送未经证实的低推理参数。只有无正文或工具输出的推理回复才可用更高预算重试一次。
- **Instead of:** 给所有角色同一个 4,096 token 输出上限，或在中转接口默认发送低推理参数。
- **Because:** 三次单请求探针均收到 HTTP 200，各同时发送 `max_tokens: 32` 与 `max_completion_tokens: 64`。结果未证明任何模型降低了推理强度：

  | 模型 | 请求推理参数 | 可证实的结果 |
  | --- | --- | --- |
  | devin-swe-2 | `reasoning_effort: "minimal"` | 782 输出，仍有推理，两个输出上限都未生效；总计 1,264。 |
  | gemini-3.8-flash | `reasoning: {effort: "low"}` | 1,215 输出，统计中仍有 124 个推理 token；两个输出上限都未生效；总计 1,236。 |
  | deepseek-v4.1-flash | `reasoning_effort: "low"` | 64 输出全部为推理，无正文；与 `max_completion_tokens` 相符，本次未采用更短的 `max_tokens`；总计 112。 |

  前两次因中转未按所发上限约束而超过预计的 1,000-token 探针预算，已按实际用量记账，未补发探针。这不是对未发送参数或单独发送任一上限的验证。

  pi-ai 的固定 4,096-token 预留会把 4,096 上下文的 Completions 输出压到 1 token。小上下文的推理模型改用输入估算和比例预留，在同一上下文内给回答留空间，不伪报模型上下文。

## 2026-11-20 - 设定集与术语表的字段

## 2026-11-21 - 工具循环按请求次数设软预算

- **Decided:** 美术导演、审稿、主控、子 Agent 这类工具循环，每个角色设一个请求次数预算（数值在角色定义里，用测试用书校准）。超过预算时，代码单独插一条系统提醒，写明已用次数、预算和硬停线：做完当前这一步就交结果，没做完的在结果里标出来。到预算的 1.5 倍时停掉当前轮次，只留提交工具，再插一条强制收尾提醒；之后 5 次请求内还没交，就中止并标“需要处理”。画师照旧只数重画次数。写法照 oh-my-pi `task/executor.ts` 的 `buildBudgetNotice` 和 `prompts/system/subagent-yield-reminder.md`。

## 2026-11-21 - 上下文维护分级，摘要可换上下文更大的模型

- **Decided:** 对话面板和美术导演的长循环按代价从低到高处理上下文，每级做完重新计量，降到触发线的 0.8 以下就停：

  2. 抖掉（到触发线时先跑，不调模型）：保护区以外的大工具结果和大段剧本、JSON 换成占位加引用，原文存文件，读工具能读回来。
  3. 摘要（前两级不够时）：调模型写结构化摘要。摘要模型先用角色自己的模型；要摘要的内容放不进它的窗口时，从已配置的模型里选上下文最大、放得下的那个。

- **Because:** 长循环里占地方的主要是工具结果，大多能机械丢掉、需要时再读回来，不必每次花一次模型调用做摘要，也不丢细节。干活的模型换了，文风和费用都会变，所以只给摘要换模型。分级顺序照 oh-my-pi（`agent/src/compaction/pruning.ts`、`shake.ts`，`session-maintenance.ts` 的摘要模型候选）。
- **Decided by:** user

## 2026-11-21 - 模型调用两层重试，审核拒绝单独处理

- **Decided:** 第一层照旧传 `maxRetries: 2`，管响应头到达前的失败。第二层在 `streamFn` 外包一层整条消息重发，管流到一半断开、空回复、网关返回 200 后掉线，只在这条消息还没产生工具副作用时重发，最多 2 次。流式输出加空闲超时，超时按临时错误处理。用户取消不进任何重试。内容审核拒绝不算临时错误、不消耗重试次数：写手那章先按降敏规则改写一次，还被拒就标“需要处理”，和图片的处理方式一样。

- **Because:** 实测 pi-ai 1.6.0 的 `maxRetries` 只在响应头之前生效，长章写到一半断流会直接标“需要处理”，已经付过的 token 白花；审核拒绝按临时错误重试只会再被拒两次。
- **Decided by:** user
- **Supersedes:** 2026-11-21 - 模型临时错误重试 2 次（补第二层和审核拒绝，第一层不变）
