## A. 实测推翻或修正了文档

- **A1. 单句长度要设上限，三档改编强度要给数值定义。** 写手按"平衡"写出来的第 1 章，旁白基本照搬原文：78 句里句长中位 69 字、最长 191 字。实测对话框按 3 行设计（字号 30px，宽 78%）：1920×1080 约装 141 字，1280×720 约装 93 字。
  - **改法：** 单句硬上限是 90 个汉字，三档都一样，超过就退回写手。三档的差别不在句子长短，而在压缩多少：
    - 忠实：一段原文拆成多句，保留原句顺序。
    - 平衡：一段原文写成 1 到 3 句，长描写压短，目标句长 30–70 字。
    - 精简：一段原文可以压成 0 到 2 句短旁白（仍算覆盖了这一段），目标句长 15–45 字。
  - 检查器：超过 70 字给警告 `W_LINE_LONG`，超过 90 字报错 `E_LINE_TOOLONG`，交回写手拆句。
  - 播放器不做句内自动翻页，因为快照、已读、回滚都以句子 ID 为单位。
  - 证据：`refs/ext-2026-11-r3-text-pipeline.md` 追加节、`refs/ext-2026-11-r3-player-demo.md` 文本框容量表。按 ≤90 定稿的 `ch01.balanced-v2.nvs`，在两种分辨率下都没有超框（0/56）。
  - **后续推翻：** 本条“单句 90 字硬上限 / 报错 `E_LINE_TOOLONG` / 播放器不做句内翻页”已被 `decisions.md` 2026-11-21「句子不设硬性字数上限，装不下由播放器分页」推翻；改编强度目标句长仅作建议。
- **A2. 剧本里的素材名和出图产物各起各的名，对不上。** 剧本写 `beijing-street`、`xiangzi/ragged-white-jacket/plain`，出图产物叫 `bg-beiping-street`、`sprite-xiangzi-puller`。剧本引用的 45 个素材里，能对上图的只有 32 个。
  - **改法：** 设定集里放一张素材登记表，写手、美术导演、画师、编译器、播放器都只认这一张表的 ID。
    - 地点：`place/variant`。
    - 角色：`character/costume/expression`。
    - CG：`cg-<id>`。
    - 表情同义合并（visuals §2.1）也登记在这张表里。
  - 说话人 ID 查角色表，舞台素材 ID 查登记表，两者分开校验。
- **A3. CG 里的角色不像本人，三类图的画风也不统一。** 第一版 CG 只给了文字描述，祥子画成了动漫长发、身材偏瘦；拿立绘对比，身份一致度只有 0.12 和 0.07。现在的视觉审核也拦不住，因为它的检查项里没有"CG 角色身份"这一项。只靠一段文字描述画风，三类图之间的画风一致度是 0.33–0.41；把主视觉当参考图一起传，提高到 0.85–0.91。
  - **改法：**
    - 所有画师调用都带主视觉作参考图。
    - 场景画师画 CG 时，提示词里写上外貌，并带上出场角色的造型基准图和地点基准图作参考。
    - 视觉审核的 `identity` 一项拿 CG 去比对所含角色的造型基准图，不比对设定图。
    - `bible/style.json` 里的主视觉要真正作为参考图使用，不能只是存着。
- **A4. 透明底失败的真实样子是"没有透明通道"。** 表情差分首画 12 张里有 4 张失败，全是返回 RGB 图、把灰白棋盘格画进了像素。检查透明通道（有 alpha，且全透明像素占比 ≥0.5%）就能全部拦下；像素里的棋盘格检测一次都没有单独起作用。
  - 改 `visuals.md` 的说法：棋盘格检测保留，作为第二道。
- **A5. 构图检查改成数值判断。** 让视觉模型判断构图，结果在 0.4–0.6 之间来回漂。改由技术检查做：
  - 派生图和基准图的 alpha 外框（宽、高、中心）差值超过阈值就拦。
  - CG 和背景另加一条：显著主体落在中央 4:3 安全区内的比例 ≥ 0.70（实测 0.69–0.82，加上提示词里写的安全区句，4 张全过）。
  - 视觉审核只留 `identity`、`anchors`、`description`、`style`、`artifacts` 五项，每项单独打分、单独定阈值。合成一个总分会被表情项拉过线：实测一张锚点 0.03 的图靠表情分整体通过了。
- **A6. 背景变体不能用像素相似度判断构图。** 夜景把全图亮度都改了，SSIM 只有 0.12，但人眼和视觉审核都认为是同一构图（6/6）。
  - 改法：技术检查只查尺寸一致，构图由视觉审核的 `description` 项判断。
  - 播放器里背景变体之间默认硬切，交叉淡入淡出等实测之后再说。
- **A7. 静默改画比拒绝更危险。** 3 张最黑暗场景的提示词都没被拒，但上吊那张被模型悄悄画成了"蹲坐的女子"。
  - 改法：视觉审核的 `description` 项要核对剧本要点有没有画到。
- **A8. 错误分类不能只看 HTTP 状态码。** 中转把临时故障报成了 400，响应体里的错误代码是 `service_unavailable`。
  - 改法：适配层先看响应体里的错误代码（`service_unavailable`、`overloaded`、`rate_limit` 等），这类错误即使状态码是 4xx 也按临时错误处理。
- **A9. 章节识别规则要改的地方。**
  - 主编号规则取命中最多的一条，序章、楔子、番外、后记、凡例这类辅助标题和它取并集，不是互相竞争。
  - 裸数字标题至少命中 3 次才参与选择。
  - 目录行（带省略号和页码）一律排除。
  - 增加"本 / 折"体例。
  - 识别出 2 个以上的卷、但一章都没有时，把卷降成章。
  - 冻结规则后拿没见过的书去跑：9 个文件里 6 个全对，修复后 9 个全对。所以导入向导核对章节划分这一步不能省。
- **A10. 编码检测不用 chardet。** 顺序是：BOM → 纯 ASCII → UTF-16 字节嗅探 → 逐个编码严格解码（`TextDecoder` fatal） → 质量门 → 书写系统密度打分 → 中文散文形状门。结果判为歧义时，向导列出至多 3 种候选编码，并显示各自解出的前几行。
  - 旧代码用的 chardet 在 Big5 歧义文件上选错成了 shift_jis。
- **A11. 写手里的内心独白。** 把第三人称的心理描写标成 `(inner)` 时，必须改写成第一人称，否则留作旁白。实测文风审稿能抓到这类声口断裂。
- **A12. 预览阶段的伏笔抽多了。** 24 章抽出 42 条，其中混进了叙述者的预示和评论。
  - 改法：`foreshadowingHints` 只报读者看得见、但还没解释的钩子。
- **A13. 术语表"作品里的写法"字段被填成了书名，66 条全错。**
  - 改法：字段说明写明"同语言制作时就是原文的写法"。
- **A14. 调度器：只验证"不出错"不够。** 只检查安全性不变量时全部通过，但另有 5 个死锁 bug 只有在加上活性检查后才暴露。修法写进 M1a 规格：
  - 图片最终失败时用占位图，作品不暂停。
  - 章失败造成的暂停，不会被之后的停止、崩溃、确认覆盖；只有对失败章本身点重试才能解除。
  - "继续"只恢复本作品的任务。
  - 作品每次拿到制作槽时，都恢复自己被中断的任务。
- **A15. 放大：差分和它的基准图必须用同一个模型。** 这次实验里，表情差分用了快速档，基准图用了默认档，结果换表情时清晰度会跳变。
  - 立绘放大到宽约 2048 像素（1024×1536 → 2048×3072），不按"和背景同倍数"。
  - 快速档在设置页写明"低性能机用，画质下降"。
- **A16. 原书的注释被当成正文。** 维基文库版每章末尾的注释（"车口：停车处……"）在导入时变成了 p0029–p0038 这几段。写手为了"覆盖"它们，单开了一个"注释"场景。导入要先识别出注释、脚注、版权页这类非正文段，从正文里剔除，存成章的附注，不参与覆盖，也不进剧本。

## B. 实测证实可行，补进文档

- **B1. 覆盖恰好一次可以做到。** 写手提示词里写明"每段恰好覆盖一次"，代码再按段落范围核对，三章一次全过（38/38、33/33、46/46）。出现缺漏或重叠时，把"缺 p0007–p0011"作为诊断交回写手，和剧本检查走同一条路。
- **B2. 美术导演默认读整章。** 分批读的输入 token 是整章的 4.1 倍，补丁格式冒出 8 种写法，素材名也会前后不一。分批只在整章放不进上下文时兜底，并且要配一层补丁格式规范化。这关掉了 `agent-orchestration.md` 的一个待定问题。
- **B3. 写手一次输出整章，内部用 `scene` 块分场。** 应用按块拆开，一个场景存一个 `.nvs` 文件。这统一了 `work-format.md` 里"一个场景一个文件"和"一章写一次"两种说法。
- **B4. 剧本语法补的几处：**
  - `@hide` 可以接槽位，也可以接角色 ID。
  - `@face` 可以省略造型，写成 `char/expr`，这时按该角色当前的造型解析。
  - `@zoom` 参数顺序固定为 `[target] <倍率> [时长] [easing]`，解析器把其他顺序归一。
  - `@filter` 和 `@particle` 用 `none` 清除。
  - 单独一个 `@wait` 是等点击，`@wait N` 是停 N 秒自动往下走。
  - `@caption` 等点击时在行尾加 `wait`；字幕也是句子，带句子 ID。
  - 底稿见 `spikes-r3/text-pipeline/out/grammar-draft.md`。
- **B5. 忠实度检查的引文由代码核对，有效。** 9 条引文全部逐字落在所标的段落里。
- **B6. 降敏改写在文本侧有效。** 第 23 章重写一次后，自杀情节用委婉写法保留，段落覆盖仍然完整。
- **B7. 段落编号每章从 1 起，影响只限于一章。** 在某章开头插一段，只有这一章插入点之后的引用失效，其余 23 章完好。
  - 补：重新导入原文后，`source` 范围越界的部分收回到该章的有效区间。
  - 补：段落编号超过 9999 时扩成 5 位。
- **B8. 超长章按段落边界再切。** `MAX_CHAPTER_CHARS = 20000`，切出来的章标题加"（N）"。全文一个标题都没有时，整本作为一章"正文"。
- **B9. 播放器架构可行。**
  - 每句快照平均 381B，200 句约 76KB，恢复一次 0.1ms。
  - 第 1 章全部纹理约 235MB，证实要按引用计数卸载。
  - 让模型看截图判断"像不像视觉小说"，6 张都在 2.9/3 左右。
- **B10. 4:3 安全区：** CG 和背景的提示词里写上"主体在中央 4:3 区域"，再加 A5 的数值门槛。
- **B11. 成本。**
  - 图片：每张立绘约 0.049 美元，每张场景约 0.057 美元；100 章约 470–530 张图，约 23–30 美元，算上重画约 35–45 美元。单张出图耗时中位数 37 秒。
  - 文本：全书约 106 万 token（DeepSeek 口径约 74 万），每章制作约 3.5 万 token。
- **B12. 调度器用 5 张表管队列：** `work`、`task`、`task_dep`、`asset`、`chapter`。图片队列以 `asset` 为单位，每张图一行，重画时原地复用这一行。
  - 软依赖只在章被设为优先时才能豁免。
  - 对还没做完的章发起"重做本章"的提议，直接拒绝。
  - 预览和综合不占制作槽。
  - 安全性和活性的随机测试共 6000 组，0 违例。DDL 见 `spikes-r3/scheduler/schema.sql`。

## D. M0 规格要改的地方

依据 `refs/ext-2026-11-r3-m0-spike.md`。

- **D1.** 文本模型配置加"兼容哪家"下拉；图片模型配置加 4 项声明（文档审计 D01、D02）。M0 只存不用，但配置格式在 M0 就要定下。
- **D2.** `call()` 返回 `{ promise, cancel }`。`promise` 成功时给命令结果，失败时给 `{code, message}`。错误码加一个 `moderation`。
- **D3.** 断路器：连续 3 次没能完成 ready 握手才打开，ready 成功一次就清零；手动点"重新启动"也清零。`creator.down` 时，界面把所有在途调用以 `creator_down` 结束。
- **D4.** 主进程启动后台进程后，立刻把 MessagePort 发过去；先等 ready 再发会互相等死。
- **D5.** sharp 必须写在 `apps/desktop` 的 dependencies 里，由 externalize 排除，不能打包进后台进程的脚本。
  - Linux 上安装后运行 `tools/patch-sharp.mjs`：已打过补丁就跳过。需要 patchelf 和 objcopy。
  - CI 里的 Linux 冒烟测试要实际解码一张图。
- **D6.** `novelive://` 资源地址只能用在 `<img>` 和 CSS 里，界面里的 `fetch()` 不支持。
- **D7.** 录制回放：
  - 有 `record`、`replay`、`strict` 三种模式，单测和 CI 用 `strict`。
  - 故障注入名：`midcut`、`disconnect`、`cancel`、`http500`、`bad-image`。
  - 录制文件格式以 m0 规格为准，带 `recordedAt` 和 `tags`。
  - 响应头只录白名单（`content-type`、`retry-after`）。
  - 端到端测试用 `registerFauxProvider` 加 fetch 注入回放，不再说"本地假服务"。
- **D8.** `pnpm check` 合并成一条命令：各包类型检查 + biome + stylelint + vitest，约 14 秒。用 pnpm 12 时，`onlyBuiltDependencies` 和 `overrides` 写在 `pnpm-workspace.yaml` 里。
- **D9.** dev-bridge 默认端口：WebSocket 8765、HTTP 8766。dev-bridge 跨不过去的接口：选文件夹、资源协议。
- **D10.** 版本锁定（2026-11-21）：

  | 包 | 版本 |

  | electron | 45.4.1（内置 Node 24.22.3，`node:sqlite` 不需要开关） |
  | electron-vite | 6.0.0 |
  | vite | 7.2.7 |
  | @vitejs/plugin-react | 5.1.1 |
  | typescript | 5.9.3 |
  | react | 19.3.1 |
  | pnpm | 12.21.0 |
  | pi-ai / pi-agent-core / pi-schema | 1.6.0 |
  | sharp | 0.35.5 |
  | openai | 7.62.0 |
  | vitest | 5.1.1 |
  | playwright | 1.65.1 |
  | biome | 2.6.8 |
  | stylelint | 18.1.0 |

  不上 vite 8 和 plugin-react 6，因为 plugin-react 6 强制要求 vite 8，electron-vite 6 还没在 vite 8 上验证过；TypeScript 7 太新。

- **D11.** 崩溃横幅里的日志路径太长，会挤掉"连续 3 次"的说明。改成：说明文字放在前面，日志路径放进"日志"按钮。
- **D12.** 上下文长度是整数 token，最小 4096。配置文件读不出来或 Key 解密失败时，`config.get` 返回 `{configError: {path, reason}}`。
