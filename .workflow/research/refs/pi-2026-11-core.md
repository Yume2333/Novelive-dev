# pi 现状调研（2026-11-21）：1.6.0 + main，面向嵌入式 agent 产品

调研基线：npm `latest` = **1.6.0**（2026-11-20 发布，全包统一版本号）；仓库 `earendil-works/pi` main @ `cb1205e`（2026-11-20，123k stars）。全部 MIT，author 为 Mario Zechner / Earendil Works。所有包 `engines: node >= 22.19`。来源：本地浅克隆 + 各包 CHANGELOG/README/package.json 实读 + npm view。

一句话结论：**pi 的重心已经从 pi-agent-core 转移到了 pi-durable**。durable 是官方正在重投入的下一代运行时（p2/p3 两个应用都建在它上面），它自己实现了会话、持久化、压缩、子会话、任务编排，**不依赖 pi-agent-core**。1.5.2 → 1.6.0 的 durable changelog 里子 agent 相关能力大幅增加（signals、tools park、hook tasks、`notify`）。

## 0. "pi 2.0 支持 subagents" 到底指什么

仓库和官方渠道里**没有名为 "pi 2.0" 的产品或分支**。最接近的所指是 **`apps/p2`**——"Pi Durable UI" 原型应用（README 原话："p2 is a prototype. It will be gone soon"，"self-hosted Pi Durable UI built from independent Chord plugins"），其后继是 **`apps/p3`**（"the successor of p2 (Pi Mobile) on Chord v2"，README 说还需要 Node 26.3.1+，目前 headless 无页面）。p2 的插件目录里有完整可用的 `plugins/subagents` 和 `plugins/agent`（一次性子 agent）。

另一种可能所指：`@earendil-works/pi-durable`（官方博客 2026-10-01 称其为与 Pi 1.0 并行的 "new experimental substrate"）。durable 自身就提供子会话所有权原语，p2 的 subagents 插件只是其上的产品化封装。

第三方 npm 上另有 `pi-subagents@0.89.1`（nicobailon 的社区扩展，163 个版本，非官方）。coding-agent CHANGELOG 提到过它，仅是兼容性说明。

## 1. 子 agent 机制全景（每一个都核实过）

### 1.1 pi-durable 原生原语（`@earendil-works/pi-durable@1.6.0`，实验性）

**机制**：每个子 agent 是一个独立的 `Conversation`（独立 transcript/文档/模型/工具集），通过 ownership 挂到父级：

```ts
// 前台子 agent：工具调用 owns 子会话，abort 级联，父 idle 等子
const child = await tx.createConversation({ ownership: { kind: "task", taskId: api.taskId } });
await configure(tx, child.id, { model: haiku, tools, instructions });
const settled = await (await (await api.conversation(child, ctx))!.submit(
  { type: "input", content: args.task, requestId: `subagent:${api.taskId}` }, ctx
)).wait(ctx);

// 后台子 agent：挂在一个立即完成的 background anchor task 上，
// 父会话的 Esc/idle 边界穿不过去；abort({background:true}) 仍能够到
const anchor = await tx.createTask(Anchor, null, { ownership: {kind:"conversation"}, background: true });
const child = await tx.createConversation({ ownership: { kind: "task", taskId: anchor } });
```

- **所有权/abort 语义**：abort 自底向上级联；`background: true` 的任务是边界（父 abort 和 idle-wait 不穿越）；`fork(entryId, {ownership})` 支持分支。
- **消息回报**：后台 Reporter task 模式（`test/examples/22`）：子答案作为父会话 follow-up input 投递，`requestId` 保证幂等（恰好一次，重启安全）。
- **1.6.0 新增的相关原语**：
  - `SubmissionDraft.notify: { taskId, key }` + `SubmissionSettled` 内置 signal——子 agent 工具可以 **park**（挂起，不占进程）直到子会话交卷（`test/examples/43-subagent-waits.ts`）。
  - **Tools that park**：`execute()` 可返回 `{ sleep: { until?, signals?, checkpoint? } }` 或 `{ wait: { on, policy } }`；`cancel()` 清理外部工作。
  - **Signals**：`defineSignal({name,version,schema})` + `harness.signal(taskId, token, key, value)`——人从外部喂数据给挂起的任务（审批、webhook 都适用）。
  - **Hook tasks**：`afterTools`/`onYield` 钩子可返回 `{ tasks }`；`onYield` 的 YieldDecision `{ continue }` 可以让已生成的回答**不落地**继续返工——这正是"视觉审核/审稿"角色的现成挂载点（`test/examples/45`）。
  - **并行嵌套调用**：`api.executeTool(name, args, ctx, { key, wait:false })` → `{ taskId, result(ctx) }` + park `{ wait:{ on:[ids], policy:"any" } }`。
  - **每会话配置**：`configure(tx, id, { model, thinkingLevel, tools, modelTools, instructions, cwd, compaction })`——per-role 模型路由和 per-conversation compaction 都是一等公民。
- **能否做库跑在 Electron utility process**：**能**。`Harness.open(storage, {models, registry}, ctx)` 纯库调用；存储可选 `openNodeSqliteStorage(path)`（基于 Node 内置 `node:sqlite`，WAL）/ JSONL / Memory / IndexedDB。无 TUI、无 server 依赖；但拖入 `@earendil-works/chord` 对象运行时（dist ~12MB）+ pi-codemode（QuickJS wasm）+ pi-schema + pi-telemetry + photon(wasm)。README 顶部明确警告 "Experimental. The API changes without notice between releases."（1.6.0 确实有 breaking：`RunEndTask`→`HookTask`、工具可返回 `ToolPark`、存储格式版本升级 pi.tool v4/pi.generation v3）。
- **流式给 UI**：`conversation.watch()` 返回带窗口的 view watch（`pi.live` 文档里有 running generation 的 partial、工具运行输出）；partial 提交节流 ~100ms 可调（`settings.progress.partialIntervalMs`）。没有 pi-agent-core 那种 `message_update` 事件回调——UI 是 watch-driven diff（`ops`），需要自己映射到 IPC。

### 1.2 p2 `plugins/subagents`（`apps/p2/plugins/subagents`，原型代码，非 npm 包）

751 行 `tools.ts` + contract/worker/web/tui。**持久后台子 agent 产品化实现**：单个 `subagent` 工具，action = `spawn/send/configure/stop/archive/restore/answer/status/models`。spawn 参数含 `name, message, model("provider/modelId"), thinkingLevel, tools（父工具子集）, env, cwd, followSession`。子 agent 间有 `team` 工具互发消息（`p2.agent-message` entry）。关键文件：

- `contract.ts`：`Subagents` remote contract（Chord evolve v2→v3）、`Child` schema、`SubagentControl`。
- `contract.worker.ts`：`Subagents` durable doc（`{agents, reporters, oneShots}`）、`resolveChoice()`（模型/thinking/工具解析，与一次性 agent 共用）、`InheritedLocation` doc。
- `tools.ts`：`createSubagentExtension(models, locator, access)` → `Extension`（`defineP2Tool` + Anchor/Reporter tasks）；`settledOrWithdrawn`、`placeSubagents`（own-location 迁移）。
- **状态**：p2 整体是将被替换的原型（"Do not build on it"），但这段代码是 durable 子 agent 模式的**最佳完整参考**——Novelive 可以直接把 Anchor/Reporter/registry-doc 模式抄到自己的 durable 或自研编排上。不能作为库依赖（import `@p2/app/v1`，p2 私有 API）。

### 1.3 p2 `plugins/agent` + codemode `tools.agent`（一次性子 agent）

`apps/p2/plugins/agent/tool.ts`（~170 行）：`tools.agent({prompt, schema, label?, model?, thinkingLevel?, tools?})` —— **只能从 code mode 脚本里调用**（`callers:["tools"]`，模型本身调不到，避免阻塞 turn）。每次调用开一个新会话，最终回答 JSON.parse + `pi-schema` 校验，失败回喂错误重试最多 3 次，`structuredOutput` 返回解析值。`replay:"safe"` + `AgentRun` doc 保证重启后重连同一会话。这是实现"写手/画师"批量扇出的理想参考：结构化输出 + per-call 模型选择。

`apps/p2/docs/workflows.md`（190 行）给了四个编排模式，全部用 `tools.agent` + `Promise.all` 写成 code mode 脚本：

1. **Fan-out + 对抗验证**：N 个 reviewer → 每个 finding 派独立 verifier（**异构模型**，指示"设法反驳"）→ 只回报 confirmed。
2. **多角度草稿 + 裁判**：3 个不同约束的 draft → 一个高 thinkingLevel 的 judge 核对代码、打分、合并。
3. **修复直到通过**：`tools.bash` 跑检查（真实退出码）→ 错误喂给 fixer agent → 连续两轮无进展退出，上限 5 轮。
4. **搜索直到无新发现**：每轮把已知 id 列表塞 prompt，一轮零新增即停。

实践要点（直接适用 Novelive）：小 schema（required/enum/maxItems/maxLength）、`Promise.all` 里每个 `.catch` 兜底、verifier/judge 用不同模型家族、绝对路径 + 明确只读声明、扇出和轮次设上限、便宜模型做广角 + 强模型做 judge、只返回摘要（返回值进主上下文）。限制：脚本占住主 turn（无后台运行）、无并发上限、一次性 agent 不能从 UI 再对话（要 follow-up 用持久 subagent）。

### 1.4 coding-agent `examples/extensions/subagent`（官方示例，~1257 行）

`packages/coding-agent/examples/extensions/subagent/`：**子进程方案**——每个子 agent 是 `spawn()` 出来的独立 `pi` CLI 进程（`--mode json` 事件流回父）。特性：markdown frontmatter 定义 agent（`name/description/tools/model` + system prompt），`~/.pi/agent/agents/` user 级 + `.pi/agents/` project 级（project 默认不加载，需 `agentScope`），三种模式 single/`tasks[]`并行（≤8，并发 4）/`chain[]`（`{previous}` 占位符），usage 统计透传，abort 级联 SIGTERM→SIGKILL。配套 workflow prompts：scout→planner→worker 等。**状态**：官方示例代码，非发布包；思路可参考（进程隔离、frontmatter 定义），对 Novelive 的嵌入式场景不适用（不应 spawn pi CLI）。

### 1.5 pi-agent-core 套娃（无框架支持，依然是兜底）

`pi-agent-core@1.6.0` 没有任何子 agent 概念；照旧做法：子角色 = 另一个 `Agent` 实例，父 `AgentTool.execute` 里 `await subAgent.prompt()`，父 `onUpdate` 透传子的 `AgentEvent`。轻、无持久化，崩溃恢复全靠自己。

### 1.6 durable `durable/codemode` 扩展（`@earendil-works/pi-durable/codemode`）

`createCodemodeExtension({sandbox: new CodemodeSandbox({memoryLimitBytes})})` 给会话加 `codemode` 工具：模型写 JS，`await tools.<name>(args)` 调本会话工具为嵌套调用；**脚本可重启恢复**（QuickJS 确定性重放 + journal：已完成嵌套调用按 key 重连，不重跑）。加上 `callers`/`modelTools`/`deferred` + `tool_search`（`@earendil-works/pi-durable/tool-search` → `createToolSearchExtension()`），构成完整的 "模型只看到一个 codemode 工具、脚本扇出调其余工具" 的 MCP/code-mode 架构——p2 的 `tools.agent` 就是架在这上面的一个工具。

## 3. 1.5.2 → 1.6.0 与 main 上对 Novelive 重要的变化

**pi-agent-core**：仅一个修复——abort 打断的批量工具调用现在每个都写 "Operation aborted" 结果进 transcript（#9986）。API 无变化。

**pi-ai**（与 Novelive 相关项）：
- 新增 `session-resources` 导出：`registerSessionResourceCleanup()`/`cleanupSessionResources(sessionId)`——多会话产品必须调（释放 Codex WebSocket、Anthropic message-thread 状态、strict-mode 降级记忆）。**这直接对应 Novelive 的多会话 session 清理**。
- `strict:"prefer"` 工具在 schema 有无 `type` 节点（如 `items:{}`、TypeBox `Type.Unknown()`）时自动降级 non-strict（#12049）——SillyTavern 式自由 schema 更安全。
- Anthropic message threads 现在默认对任何 baseUrl 在 api.anthropic.com 的 provider 开启（服务端续传，省 token）；`compat.supportsMessageThreads` 可关。
- 大量 provider 重试修复（ECONNRESET/EPIPE/connection closed/gateway 错误现在都进 retry）。
- 新模型：GPT-6.2 Astra/Sol（Codex 默认换成 Sol）、Claude Fable 5.2、Qwen token plan 更新。

**pi-durable**（1.6.0 是大版本，多个 breaking）：上面 §1.1 列的 signals / tools park / hook tasks / `SubmissionDraft.notify` / per-conversation compaction settings（1.5.1 加入）/ `onAbort:"keep"` 输入 / `createFitImagesExtension`（图片按模型限制缩放后再入 transcript，prompt cache 不失效）——**最后这条对 Novelive 的画师→视觉审核链路直接有用**。

**pi-coding-agent**：主要是 TUI/CLI 修复 + GPT-6.2；对 SDK 用户：`AgentSessionRuntime.takeUnreportedDiagnostics()`、`session_start` 事件修复。find 工具 glob 语义变化。

**关于 2.0**：无任何官方 2.0 公告。官方叙事是 "Pi 1.0（稳定 CLI）+ Pi Durable（实验性下一代）"，p3 是 durable 应用层的后继。earendil.com 博客最新动作都是 durable/chord。版本号上所有包统一走 1.x 滚动发布。

## 5. 对 Novelive 的关键判断

1. **两条路线必须二选一**（或分层）：(a) `pi-ai + pi-agent-core` + 自研编排/存储——轻、稳定、自己掌控，子 agent 全手写；(b) `pi-ai + pi-durable`——崩溃恢复、会话持久化（SQLite）、压缩、子会话 ownership、信号/审批、code-mode 扇出全部免费，代价是实验性 API（每个 minor 都可能 breaking）+ chord/codemode/wasm 依赖体积 + watch-driven UI 模型要适配 Electron IPC。
2. 若选 (b)，Novelive 的角色映射几乎一对一：持久角色（整理/主控/写手/美术导演/画师）= durable 后台子会话（Anchor+Reporter 模式）；视觉审核/审稿 = `onYield`/`afterTools` hook task 或 verifer 型一次性 agent；批量画师扇出 = `tools.agent` 式 schema 校验一次性 agent + `Promise.all`；人工审批 = `defineSignal` + tool park。
3. 若选 (a)，照抄 durable/p2 的**设计**而非代码：ownership（task owns conversation）、background 边界、`requestId` 幂等、答案作为 follow-up 回投、`structuredOutput` schema 校验重试 3 次。
4. pi-ai 1.6.0 的 `cleanupSessionResources(sessionId)` 必须纳入会话生命周期，否则 Codex/Anthropic 线程状态泄漏。
5. pi-schema vs TypeBox：pi 生态已全面转向 pi-schema（零依赖、无 eval、coerce）；Novelive 现有 TypeBox 代码不用换（pi-ai 接受任意 JSON Schema + TypeBox 的 Static 类型互通），新写的工具 schema 建议直接用 pi-schema builders。
