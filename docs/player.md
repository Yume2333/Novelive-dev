# 播放器

说明 Novelive 播放器的运行方式、演出与文本能力、推进控制、进度状态以及更新迁移行为。

## 运行方式

- **只读读取**：播放器以只读方式读取导入的 `.novelive` 作品包或本机工程中的可玩章节，不修改原文件。
- **加载时编译**：作品包中存语义化剧本、设定集、术语表和分层素材（见[作品格式与工程](./work-format.md)），播放器加载时现场编译。
- **不依赖模型与创作端**：玩家和创作者使用同一个应用，不配置模型也能导入作品包游玩，播放过程不调用模型，播放器也不依赖创作端。

- **舞台渲染**：舞台层用 PixiJS 8，代码直接控制舞台对象，不用 `@pixi/react`（舞台状态是纯 JSON 快照，按字段同步到 Pixi 对象比走 React 树直接）；界面层仍是 DOM。粒子、滤镜和换表情混合靠 Pixi 实现。播放器内核分两层：一份纯 JSON 的舞台逻辑状态（背景、各槽位立绘、CG、前景、镜头、粒子、滤镜、当前文本），和提交后的渲染状态。演出指令执行时只写逻辑状态，统一提交点同步到画面；快速预览、存档和回滚都读写这份 JSON（做法照 WebGAL 的两态舞台，MPL-2.0 按文件级 copyleft 重写不拷）。
- **内置粒子的实现**：`@pixi/particle-emitter` 不支持 Pixi 8，雨、雪、樱三个内置粒子是我们自己写的小型发射器（`ParticleContainer` 逐帧更新，参数只有强度、速度、风向角度）。
- **滤镜的实现**：内置滤镜用 `pixi-filters` 6.x（MIT）：`blur` 用 Pixi 核心 `BlurFilter`，`brightness` 用 `AdjustmentFilter`，`sepia` 用核心 `ColorMatrixFilter`，`glitch` 用 `GlitchFilter`。

## 演出与文本

### 舞台比例

- 舞台以 16:9 为基准；背景和 CG 生成时主体落在中间的 4:3 安全区（见[视觉管线](./visuals.md)）。
- 各种横屏比例（16:10、4:3、手机横屏、21:9）统一铺满窗口、裁掉多出的部分，不留黑边；不做竖屏。

### 演出能力

- 背景切换和过渡；同一地点的背景变体之间默认硬切（不带过渡），暂不做交叉淡化，后续视效果补充
- 立绘上场、退场、移动、换表情、换造型
  - 换表情：同槽位、同尺寸时用 200ms 的淡入淡出混合（默认值，编译器参数可调），画面不跳；尺寸不一致时退回旧图淡出、新图淡入（派生图尺寸约束见[视觉管线](./visuals.md)）。立绘按位置槽管理，同槽位换表情或造型时保留已有位置、变换和层级（见[作品格式与工程](./work-format.md)的槽位规则）。
- CG、前景层
- 镜头对焦、缩放、震动
- 粒子、遮罩和画面滤镜

### 文本

**文本类型**有四种：

- **对白**：角色说出口的话，显示说话人名字。
- **内心独白**：角色心里想的话，显示名字，样式和对白区分开。
- **旁白**：叙述者的话，不显示名字。
- **字幕**：不进文本框，单独显示在画面上，比如时间地点卡、章节标题。

每句话可以单独指定显示名（比如身份揭晓前的“神秘少女”“???”），内部仍认作同一个角色。

**文本标记**是一句话里局部文字的效果。内置七种：强调、加粗、弱化、小声、大喊、扭曲、高亮。作品还可以自定义标记，样式由作品自己定义。

**注音**：在字的上方标读音或原名，比如日文汉字上标假名、译名上标原名。

**停顿与变速**：一句话中间可以停顿，某几个字可以出得更快或更慢。

- 停顿或慢速出字时点击，直接补完整句。
- 自动播放照常停顿和变速；跳过已读忽略它们。

### 文本的实现

四种文本和对话框都用 DOM 覆盖层渲染，不进 Pixi 舞台：Pixi 文本没有 CJK 禁则也没有注音，DOM 这边浏览器全给。

- **禁则与混排**：`line-break:strict` + `word-break:break-word` 管禁则，`text-spacing-trim:space-first` 做标点压缩，`text-autospace:normal` 做中西文自动空距；禁则靠 Chromium，不自实现。
- **描边**：用 `text-shadow` 出文字轮廓，不用 `-webkit-text-stroke`（多笔画字内腔会糊）。
- **注音**：`{ruby 读音}字{/ruby}` 编译成 DOM `<ruby><rt>`。
- **逐字打字机不跳行**：两层 DOM——隐藏层渲染整句、撑开排版（`visibility:hidden`），显现层叠在上面逐字显示；文字逐字出现时不会重排换行。
- **字体**：对白默认思源黑体（Noto Sans SC），和界面统一；应用内置字体带全字库，生僻字也不会显示成方框。作品自己带的字体见[作品格式与工程](./work-format.md)的自定义样式。
- **对话框容量**：对话框按 3 行设计（默认字号 30px、盒宽 78%）：1920×1080 约装 141 个汉字，1280×720 约装 93 个汉字。作品语言、窗口大小和作品自定义样式（字号、盒宽）都会改变容量，所以剧本不按字数卡句长，装不下由播放器分页。
- **句内分页**：隐藏层排完整句后，按行数切成若干页，显现层每页显示一段行（按页平移，不重新排版），尽量在标点处断页。点击先翻完本句的页，再进下一句。页码不存：存档、读档、回滚、跳回都回到这句的第 1 页，已读仍按句子 ID 记，跳过已读时整句略过；回看记录显示整句。行内标签按整句排版生效，跨页的文本标记两边都带样式，停顿和变速按显示顺序照常执行。

## 推进与控制

### 点击推进

文字还在逐字出现或动画没播完时，第一次点击补完这一句，第二次点击才进入下一句。哪些位置等点击由剧本决定（见[作品格式与工程](./work-format.md)的“推进节奏”）。

### 控制项

- 自动播放
- 跳过已读
- 历史记录（可以跳回，跳回后可以再前滚）
- 隐藏界面
- 文字速度、字号和对话框不透明度
- 全屏
- 对话框样式选择
- 快速存档 / 读档（快存 1 槽）
- 普通存档位（60 槽）
- 回滚（可以跨章）
- 章节目录跳转

**跳过与回滚的实现**：

- 历史记录就是回滚栈：每句文字落点时存一份完整舞台状态快照，上限 200 条。快照只存素材引用和状态 JSON，不存图片本体（典型章节每句快照约 381B，200 条约 76KB，恢复一次约 0.1ms）。历史列表读这些快照显示；跳回历史里的某一句 = 恢复那一幕的快照再重演演出，存档同样是舞台快照加当前位置。
- **快照字段**：

  | 字段 | 内容 |
  | --- | --- |
  | 背景 | 当前背景素材名与过渡状态 |
  | 立绘 | 各位置槽的素材名、位置、变换、层级 |
  | CG / 前景 | 当前 CG、前景层素材 |
  | 镜头 | 对焦、缩放、震动等变换 |
  | 粒子 / 滤镜 | 活动中的粒子与画面滤镜 |
  | 文本 | 当前句文字、说话人与显示名 |
  | 活动演出清单 | 还在进行的演出（见下一条） |
  | 章内进度 | 当前场景与句子位置 |

  第一版没有 BGM、变量和 Live2D，快照不含这些。

- **活动演出清单**：快照里带一份还在进行的演出清单。恢复快照后按三类处理：意图型状态写指令（`@bg`、`@show`、镜头、滤镜、粒子等）幂等，直接重跑；文本句只重建文本演出，不重跑整句；累积型、相对动画跳过，防叠加。
- 回滚栈回退不弹栈，只移动指针：回滚后可以继续前滚回到最新位置；一旦播了新句子，指针之后的记录作废。
- 回滚和跳回经过的句子都算已读。跳过已读按句子 ID 判断：只在已读集合内的句子快速略过（停顿和变速照常忽略），遇到未读句就停；不做跳过未读。
- 跳过已读时舞台指令照常瞬时生效：转场跳到终态、立绘换图立即到位，只有文字秒出、不停顿。
- **自动播放的停留时间**按每页的字符数线性算：默认 `1.2 秒 + 0.08 秒 × 字符数`，设置里的滑块调倍率。
- **文字速度**用“毫秒 / 字”滑块，范围 3～153ms，另有一档“瞬间”（0ms）。
- **素材预载**：从当前位置向前看 32 句预载图片（默认值，可按剩余显存在 20～32 句区间取）；舞台素材按引用计数管理，既不在预载窗口内也没有舞台引用的纹理才卸载（`Assets.unload` + `texture.destroy(true)`）。2K / 4K 下一幕的纹理有 100～300MB（典型章节全部纹理约 235MB），卸载时机必须按这条执行。

## 进度与特殊章节

### 存档位置

存档和已读记录统一放在应用数据目录，按作品 ID 分开，自己工程里的作品也一样。导出作品不会带上存档，作品更新时也只在这一处迁移。

存档条目带缩略图（480×270 WebP）：存档时把舞台画面截一张存进去，存档列表显示。

### 重看与主线进度

从章节目录打开已读过的章节时进入“重看”状态，不改变主线进度；主线进度只往前走。

### 制作中作品的章末行为

本机还在制作的作品，读到最新一章末尾时：

- 显示下一章的制作进度。
- 如果一直停在播放器，下一章做完就自动载入开头，等玩家点击。
- 应用在后台时发系统通知。

### 需要处理章节

图片最终失败的章节标为“需要处理”（见[创作流水线](./creation-pipeline.md)），使用三类占位图（角色、背景、CG）也能游玩。

## 更新后存档迁移

作品包有版本（见[作品格式与工程](./work-format.md)）。玩家导入同一作品的新版本时先提示，确认后替换旧版，存档和已读记录按 ID 迁移。迁移时对不上的旧存档保留；快照里缺的字段补默认值，越界的位置收回到有效范围内。

## 暂不做与以后可能做

- **以后可能做**：BGM、音效、TTS 第一版不做，以后可能加；分支剧情、好感度、多结局以后可能加。
- **不做**：网页播放器、骨骼动画和 Live2D。
