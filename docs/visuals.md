# 视觉管线

说明视觉素材的层级组织、参考来源、生成要求、技术检查、占位图与过期重生成规则。

## 1. 素材层级

视觉素材分为三类：

- **角色**：`角色 → 造型 → 表情`
- **地点**：`地点 → 变体`
- **CG**：单独一类

同一系列的作品可以共享素材，下级的卷或作品可以覆盖（详见 [作品格式与工程](./work-format.md)）。不做骨骼动画和 Live2D。

## 2. 角色、参考来源与确认点

### 2.1 角色分类与立绘规范

- **可复用与一次性角色**：角色分为可复用角色和一次性角色。可复用角色先建完整参考，长期复用；一次性角色只画当前场景要用的，之后再出场时升级为可复用角色。
- **角色一致性**：造型基准图参考角色设定图（或上一套造型）重新画；表情从所在造型的基准图编辑派生，只改脸部，姿势和位置不变，播放器里换表情时立绘不跳。派生图没有透明通道或尺寸和基准图不一致时由技术检查拦下，画成别人时由视觉审核拿基准图对比拦下。
- **立绘构图与对齐**：立绘画膝上或半身，按头顶或腰线对齐。
- **表情**：新建角色时先登记一套基础表情，写手写剧本时用到新表情就直接登记；表情第一次在剧本里用到时才画（见[设定集与术语表](./bible.md)）。美术导演列图清单时做同义表情合并：未登记的表情先和已有表情比对，意思相同就改用已有的。表情差分始终从已接受的基准图编辑派生，不从另一张差分再派生。差分画师按保存的表情描述写眉、眼、嘴的动作（如 `angry` → 眉下压聚拢、眼睛眯起瞪视、咬紧牙关），不写情绪单词。“其余保持”清单由代码从角色外貌字段拆出传入；缺少结构化外貌时，角色总描述只作保持人物一致性的补充，不替代表情描述。两类信息同时给编辑提示词和视觉审核用。

### 2.2 参考来源与确认点

参考来源分三种，不做联网搜图（以后可能做）：

1. 创作者提供的参考图。
2. EPUB 插图（EPUB 导入在 M4，此前该来源不可用）：由模型筛选后，作为候选放进“角色设定 / 主视觉”确认点。
3. AI 生成：没有参考时，AI 按书中描写出几版角色设定供创作者挑选（每个主要角色每套造型候选默认 3 版）。

“角色设定 / 主视觉”是制作流程的第一个确认点（见 [创作流水线](./creation-pipeline.md)），只覆盖第一卷的主要角色；其余角色第一次出场时，立绘画师按设定集描述直接画造型基准图，不停下确认。已经有参考图时是否停下确认，由作品设置里的开关决定。

### 2.3 出图分工

要画的图由三个画师分工，各自有内置提示词，自己调用生图工具，按技术检查和视觉审核的结论决定是否重画；一张图最多重画「生图失败重试次数」次（默认 3），用完用占位图并标“需要处理”：

- **立绘画师**（主模型）：造型基准图，竖版透明底。
- **场景画师**（主模型）：背景基准图和 CG，16:9，主体在 4:3 安全区。画黑暗场景（暴力、死亡）时默认用光影、剪影、留白表现，直白的描写交给剧本文字；降敏改写仍是审核被拒后的兜底。
- **差分画师**（快速模型）：表情差分和背景变体，从基准图编辑派生，只改一处。

生图通常带上 `bible/style.json` 记录的画风参考图（图片文件存 `assets/style/`，含主视觉 1 张和最多 2 张补充参考，见 2.5），提示词写明只参照画法。造型基准图缺少外貌、锚点、主色及当前服装描述时，由设定集的角色描述补足，画师与视觉审核共用这份简报。没有角色身份参考图时，生图只用文字画风描述，不传画风参考图，以免照搬其中的人物；视觉审核也只按同一份文字描述判定画风是否通过，参考图仅供非阻断建议。场景画师画 CG 时再加上出场角色的造型基准图和该地点的地点基准图（若有），提示词里写上角色外貌；CG 的参考图最多（画风参考 1–3 张 + 地点基准 + 各角色造型基准）约 4–8 张，在接口上限（16 张）内。

要新画的图进入出图队列：同一张图只画一次，基准图画完它的差分才开始画，同时画的图不超过「同时出图数」（默认 8）。

生图工具传多张参考图时，由工具按派生类型在提示词头部生成每张图的角色声明句（如“第 1–3 张是画风参考，只参照画法，不照搬里面的人物；第 4 张是 `lin-xiao` 的造型基准图”；画风参考的声明原文见 2.5），画师不写这句。提示词的完整拼装见 2.4。

实际花费按次记录并显示在用量统计面板中，参考数字见 `.workflow/decisions.md` 与 `.workflow/research/`。

内容审核拒绝不算临时错误：先按降敏规则改写一次，再被拒才用占位图并标“需要处理”（见[创作流水线](./creation-pipeline.md)）。降敏规则写进画师内置提示词：去掉武器、血液、身体部位、年龄词等具象名词，改成光影、氛围、剪影描写，角色用外观特征不用年龄词；重画时由工具把固定句“上一次生成被内容审核拒绝，请收敛描写”追加到提示词尾部，不让画师自己猜往哪改。

审核拒绝的识别按各家报错形状归成一类：OpenAI `error.code=moderation_blocked`；火山 `error.code` 为 `Input|Output{Text,Image}SensitiveContentDetected.*` 一族；阿里百炼 `invalid_request_error` + `InvalidParameter` 且 message 含敏感或审核字样；Together、SiliconFlow 的 422 safety 命中；中转透传上游的 `error.code`/`message`，按关键字匹配。审核拒绝不耗 SDK 重试（SDK 本来就只重试 429、5xx 和连接错误，400 不重试）。

差分画师将来可以换本地或第三方编辑模型时，Qwen-Image-Edit 是备选记录（开源权重，支持多图一致性编辑），当前仍走 OpenAI 兼容图片接口（适配规则见「图片接口适配」一节）。

### 2.4 出图提示词

`draw_image { content }` 的提示词由工具拼装，画师只写其中的内容段（`content`）。让模型自由写整段提示词，出来的是图片模型的默认画风：细节过密、边缘碎、处处高光。

表情差分使用独立的局部编辑提示词：保存的表情描述和画师的五官动作说明在前，随后给出保持人物一致性的上下文，不拼入画风描述或画风固定句。其他图片的拼装顺序如下，拼成一段连续文字，不用 `Scene:`、`Subject:` 这类标签行（标签格式无法约束画风）：

1. **参考图声明**（代码）：逐张写明角色，见 2.3；画风参考的排序和声明见 2.5。
2. **素材类型句**（代码）：立绘、背景、CG、表情差分、背景变体各一句固定说明。
3. **内容段**（画师）：规则见下。视觉审核的 `feedback` 和审核拒绝的固定句由工具接在内容段之后。
4. **角色外貌**（代码）：立绘和 CG 从设定集外貌字段原文拼入，含锚点特征，画师不转述。
5. **画风描述**（代码）：`bible/style.json` 里的画风描述原文。
6. **构图与输出约束**（代码）：
   - 立绘：从头顶画到膝盖上方，腿在膝盖上方被画面底边裁断，人物居中，头顶留少量余量；透明背景，没有地面和影子；半透明边缘的颜色和相邻的衣服或皮肤一致。
   - 背景和 CG：主体在中央 4:3 区域，左右两侧只画延展配景；背景另写“空景，画面里没有人”。
   - 差分：只改一处，其余和第 1 张一致，并逐项列出“其余保持”清单（keep-list）。
7. **画风固定句**（代码，固定放在最后一行；立绘和 CG 在它前面紧接一句颜色锁定句，见 2.5）：`Finish this as a final, fully cleaned-up illustration: inked line art with no sketch lines, stray hairs or broken strokes; flat base colors with smooth airbrushed gradients; highlights placed as a few clean, deliberate shapes, as in Image 1. Put fine detail only on the face, eyes, hair ornaments and the main object of the scene; keep clothing folds, background and secondary areas simpler, with fewer lines. Every outline is one clean stroke, not several sketchy ones; hair strands end in clean tapered points; lines never break or wobble. large simple color masses, low visual frequency, restrained edge density, clear edge hierarchy, minimal internal contour lines, broad shadow shapes, suppress micro-texture and micro-contrast, no unnecessary specular highlights, except that hair highlights, eyes, the gradients, and the brushwork and stroke texture of Image 1 stay exactly as in Image 1.`

   依次是成稿措辞、细节分主次、线条收尾、渲染块和例外句。单独使用渲染块会压掉参考图的高光、渐变和笔触质感，因此保留末尾例外句，在抑制布料和大面分层碎纹理的同时保留厚涂、颗粒感等画风特征。

固定句是 `creator` 包里的英文常量；内容段、外貌、画风描述用作品语言（内容段无需译成英文）。

画师写内容段的规则，写进画师内置提示词：

- 只写看得见的东西：在哪里、什么时间和天气、光从哪来；谁在做什么、什么姿势，表情写成眉、眼、嘴的动作；必须出现的物件最多三四样。用陈述句，不写“请画”“确保”。
- 不写画风、媒介、画质、构图和镜头词，这些由代码拼。工具查禁词，命中就退回改写。禁词包括 masterpiece、best quality、highly detailed、ultra detailed、intricate、8K、4K、photorealistic、award-winning、cinematic、杰作、高质量、细节丰富、精致、超清、电影感，以及任何画师名。
- 要排除的东西用正面说法写（“空无一人的院子”），不写否定句，也不加 `Avoid:` 行（加了画面没有更干净，还可能丢掉正向要点）。
- 不添加描述和设定集里没有的人物、物件和情节。
- 重画时只改内容段里和 `feedback` 有关的那一句，其余原样保留；固定句每次由工具重新拼，画师改不到。

主视觉（确认点 1 的候选）也用同一套拼装和画风固定句生成。主视觉画得太细，碎感会传给之后所有以它为参考的图，人物也更难在不同图之间认出是同一个人。

接口参数：生图质量在图片设置中可选高 / 中 / 低（默认高，仅当协议形状为 OpenAI images 协议时发送 `quality: high | medium | low`），`complexity` 不传。推荐模型示例 `gpt-image-2.6-sunburst`（模型名仍是配置项）。

### 2.5 画风参考

画风参考只决定“怎么画”，不决定“画谁”。本节画风隔离策略（参考图声明句、多参考图组合与颜色锁定句）**未实测**，先按此规则实现与约束。

**什么算画风**：线条、上色和明暗的方式、笔触和媒介质感、细节密度、光线处理、整体色调，包括画面是彩色还是黑白（黑白算画风，黑白参考画出来也是黑白，角色的固有色用深浅表现）。**不算画风**：参考图里人物的脸、发型、发色、瞳色、服装款式和颜色、配饰、姿势和构图，这些只从设定集来。

**给几张**：主视觉 1 张，再加最多 2 张补充参考，图片文件存在 `assets/style/`，`bible/style.json` 记录引用路径与风格描述。补充参考要求和主视觉是同一画师或同一画风，尽量画的是不同角色（发色、服装差别大），最好有一张带场景。几张图里共同的东西才是画风，生图模型就不容易把某一个人的特征当成画风。补充参考来自创作者提供的参考图或 EPUB 插图，在确认点 1 和主视觉一起选定；没有就只用主视觉。不从本作品已经画好的造型基准图里自动挑。

**怎么给**：

- 每张单独传，不拼成一张：拼图会被缩小、丢笔触，格子边框和多人排版也可能被当成画风。
- 画风参考排在最前面（图 1 到图 N），角色造型基准图、地点基准图排在后面。背景变体的基准图放图 1，画风参考跟在后面。表情差分首次编辑和重试都只传已接受的基准图，限定只改眉、眼和嘴，不传画风参考图。
- 固定句里写的是 `Image 1`，由工具换成画风参考实际的编号：常规调用画风参考从图 1 起算（一张时 `Image 1`，三张时 `Images 1–3`）；背景变体的基准图占图 1，画风参考从图 2 起算（替换为 `Image 2` 或 `Images 2–N`）。
- 不对参考图去色，也不裁掉里面的人物：会连画风里的配色和人物画法一起丢掉。

**画风参考的声明句**（代码，英文常量，一张时把复数改成单数）：`Images 1–3 are style references only. Match how they are drawn: line quality, coloring and shading method, brushwork, level of detail, lighting and overall color treatment, including whether they are in color or monochrome. Do not copy the people in them: face, hairstyle, hair and eye color, outfit and accessories come only from the description below.`

**颜色锁定句**（代码，立绘和 CG 用，紧接在画风固定句前面）：从设定集外貌的 `keyColors`（见[设定集与术语表](./bible.md)）拼出，CG 里每个出场角色一句：`{name}: {keyColors}. These colors come from the description, not from the style references; in a monochrome style, show them as tones.` 写在后面，是因为越靠后的句子对结果影响越大，而固定句里反复出现 `as in Image 1`。

**审核兜底**：视觉审核的 `anchors` 一项同时逐项核对 `keyColors`，颜色画偏就不通过，`feedback` 写明哪一项偏了。

**风险最集中的地方**：串色主要发生在一个角色的第一张图，也就是造型基准图。之后画 CG 和差分都带着基准图，颜色以基准图为准。最容易出问题的是两种情况：一是没有设定图、只按文字画基准图的角色；二是主视觉来自 EPUB 插图，插图里画的就是书里的主角，拿它去画其他角色。

## 3. 生成规则与本地处理

- **透明底**：立绘的透明底由图片模型直接输出，不做色键抠图。
- **画面内文字**：招牌、信件等画面里的文字由图片模型直接画，不做文字识别校验。
- **放大与降噪（后处理）**：设置里的「后处理」有三档：关 / 放大降噪（默认）/ 双重放大降噪。放大降噪由放大程序（ncnn-vulkan 可执行文件 `upscayl-bin`，由创作端启动，走标准输入输出，不依赖 CUDA，三平台都有预编译版）用所选放大模型跑一遍，再缩放到目标尺寸；双重放大降噪先跑一遍、缩回原尺寸，再跑一遍、缩放到目标尺寸，线条更清楚、风格化更强，耗时约翻倍；关闭时不调用放大程序，创作端直接用 sharp（Lanczos）缩放到目标尺寸，不降噪。「放大档位」有三档：动漫（默认，`realesrgan-x4plus-anime`）、快速（`realesr-animevideov3-x4`，设置页写明「低性能机用，画质下降」）、保留细节（`4x-NMKD-YandereNeo`，少改原画，保留复杂纹理，适合写实或细节多的画面）。快速档用 realesrgan-ncnn-vulkan 官方包里的权重；保留细节档没有官方 ncnn 版，构建时从原始权重转换。默认把背景和 CG 处理到 2560×1440（2K），作品设置可选 4K；立绘处理到宽约 2048 像素（1024×1536 → 2048×3072），不按背景的倍数；差分和它的基准图必须用同一个放大模型和后处理档，换档会跳清晰度。放大模型只出整数倍，到不了目标分辨率时先整数倍放大、再重采样到目标尺寸；透明立绘的 RGBA 整图送进模型，不拆通道。转 WebP、缩放、缩略图等其他图片处理在创作端进程里完成（进程划分见[系统架构](./architecture.md)）。
- **存储格式**：图片默认存为有损 WebP（质量 90，保留透明通道），应用设置里的全局开关可改无损。

## 3.1 画面规格

- **舞台**：以 16:9（1920×1080）为基准；各种横屏比例（16:10、4:3、手机横屏、21:9）统一铺满窗口、裁掉多出的部分，不留黑边；不做竖屏。
- **背景和 CG**：直接按 16:9 生成，提示词要求主体落在中间的 4:3 安全区、上下留余量；铺满裁切时主体不受影响。
- **立绘**：竖版、透明底。
- **背景变体**：同一地点的变体（白天、夜晚、雨天）从该地点的基准图编辑派生；播放器里变体之间默认硬切，暂不做交叉淡化，后续视效果补充。
- **模型能力**：不让用户声明图片模型能做什么。设置页测试图片模型时依次试文生图、透明底、图片编辑三项，分别显示结果；制作时用到某项能力而接口不支持，就按 3.2 报错，不做兜底，由创作者换模型或改设置。

## 3.2 图片接口适配

生图走 OpenAI 兼容图片接口，但各家实现不一样。用户不声明接口能力：图片模型配置只有接口地址、API Key、模型名、同时出图数（默认 8）、生图失败重试次数（默认 3）、生图质量（高 / 中 / 低，默认高）、原生长边上限（档位，默认 1536）、后处理（关 / 放大降噪 / 双重放大降噪，默认放大降噪）和放大档位。各家的字段差异由适配层按接口地址识别，界面不展示；认不出的地址按 OpenAI images 协议处理。

各家差异的精简对照：

| 接口 | 编辑 | 透明底 | 尺寸 | 返回 |
| --- | --- | --- | --- | --- |
| OpenAI（`gpt-image-2.5/2.6-{sunburst,flare}`） | `/edits` multipart，最多 16 张参考图 | `background:transparent` | 任意 `WxH` | 恒 `b64_json` |
| Seedream（火山方舟） | 无 `/edits`，图生图走 generations 的 `image` 字段；5.5 / 5.0 pro / 5.0 flash 最多 10 张参考图，5.0 lite / 4.5 / 4.0 最多 14 张 | 5.5 文生图和图生图都能出；5.0 pro / flash 只在输入恰好 1 张透明 PNG 时能出；5.0 lite / 4.5 / 4.0 不能 | `1K/1.5K/2K` 档或 `WxH`，按总像素限范围：5.5 / 5.0 pro / flash 为 1280×720–约 2153×2153（4624220），5.0 lite / 4.5 为 2560×1440–4096×4096，4.0 为 1280×720–4096×4096；宽高比 1:16–16:1 | 默认 `url`（24h），可要 `b64_json` |
| Qwen（阿里百炼兼容模式） | 无 `/edits`，generations 传 `image` | 2.1 系按提示词自动出 alpha | `WxH`（512²–2048²） | 默认 `url`（24h），b64 仅 3.0 系 |
| Gemini 兼容 | 无 `/edits` | 不支持 | `extra_body.aspect_ratio` | `b64_json` |
| SiliconFlow | 部分模型（`image`/`image2`/`image3` 字段） | 不支持 | `image_size` 固定枚举 | `images[].url`（1h，非 `data[]`） |
| new-api / one-api 系中转 | 看渠道（透传或翻成 generations+image） | 看上游 | 透传上游语义 | 归一成 `data[]{url,b64_json}` |

适配层在 `draw_image` 内部做归一化：

- 画师只写内容段，不写反向提示词：图片模型没有 negative prompt 参数，写成 `Avoid:` 行易使正向要素丢失（见 2.4）。各家原生的 `negative_prompt` 参数第一版不用。
- 没有 `/edits` 端点的接口，编辑请求降级为 generations + `image` 字段（Seedream、Qwen、部分中转走这条）。
- 返回 `url` 的下载成字节归一（Seedream、Qwen、Together 默认 url，SiliconFlow 只有 url）。
- 尺寸按各家规则吸附到合法值：尺寸一律以像素给出，两边取 16 的倍数。返回的尺寸可能和请求不同：宽高比差在 1% 以内就缩放到目标尺寸；超过 1% 就从中心裁成目标比例，再做安全区检查。主视觉生成后同样先裁成 16:9 再存。
- **原生长边上限**：图片模型配置里选一个档位，请求尺寸的长边不超过它，超出目标分辨率的部分由本地后处理放大。档位：1536（Codex 渠道，默认）、2048、2560（OpenAI 官方 API）、2816（Seedream 5.x）、3840（4K：OpenAI 官方 API 实验性、Seedream 4.5 / 5.0 lite）。Codex 渠道上游原生生成的长边约 1536 像素，请求更大尺寸只会被上游放大，细节不增加；OpenAI 官方 API 的 `gpt-image-2.5/2.6` 支持任意 `WxH`（两边 16 的倍数，宽高比 1:3–3:1，最大 3840×2160，超过 2560×1440 为实验性）；Seedream 5.x 的 2K 档 16:9 为 2816×1584。适配层按档位定长边，短边按画面比例算并取 16 的倍数，再按接口的像素范围吸附：超过上限就等比缩小，低于下限就等比放大（Seedream 4.5 / 5.0 lite 最小 2560×1440，选低档位时也会按这个尺寸请求）。1536 档下 16:9 用 1536×864、立绘用 1024×1536；3840 档下 OpenAI 的 16:9 用 3840×2160。
- **生图质量**：图片模型配置里的“生图质量”（高 / 中 / 低，默认高）按 `quality: high | medium | low` 发送；适配层认出接口没有这个字段时（如 Seedream、Qwen）不发，这时这项设置不起作用。
- **Seedream 的固定参数**：恒传 `watermark:false`（默认会加“AI 生成”水印）和 `response_format:b64_json`；要透明底时同时传 `background:transparent` 和 `output_format:png`（`jpeg` 加透明底会报错，5.0 系默认输出 `jpeg`）；不传 `quality`。返回的 `data[].background` 是实际透明类型，和技术检查的 alpha 检查一起用。参数错误码 `InvalidParameter.UnsupportedParameter` 判为能力不支持；`SensitiveContentDetected`、`*RiskDetection` 一类判为审核拒绝；`RateLimitExceeded`、`ServerOverloaded` 判为临时错误。提示词官方建议中文不超过 300 字、英文不超过 600 词，超出不报错，但细节容易被忽略。
- 能画全部素材的 Seedream 型号只有 5.5。立绘要透明底又要带画风参考：5.0 pro / flash 只接受 1 张透明 PNG 作参考时才出透明底，会被拒；5.0 lite / 4.5 / 4.0 不能出透明底。图片模型只有一个配置，所以这些型号画到第一张立绘就会按“接口不支持时报错”暂停。
- **接口不支持时报错**：用到编辑、透明底或某个尺寸时，接口拒绝（端点不存在、参数不支持），就判为“图片模型不支持这项能力”。这类错误不重试、不用占位图顶上，整部作品暂停制作并报错，写明是哪项能力、该怎么处理（换图片模型，或调低原生长边上限），改好后继续。
- **透明底回退**：要求透明底的文生图或编辑请求如果返回没有 alpha 通道的图，先在本地去背景，再走同一套透明底和技术检查。本地去背景不可用时，主视觉确认跳过缺少有效候选的角色造型，制作时可用占位图发布并记录原因；不会采用无透明底的原图。本地处理失败或复检仍无 alpha 通道时按能力错误暂停；如果有 alpha 但透明像素不足、画了棋盘格或其他技术检查不通过，仍按第 4 节重画或使用占位图。
- 第一版不开生成过程预览（`stream` 只有 OpenAI、OpenRouter 和 Seedream 老型号支持）；OpenRouter 图片接口第一版不接（不是 `/v1/images/*` 形状）。
- Gemini 兼容接口可以填，但它不能编辑也不能直接出透明底；拒绝编辑或透明底参数时按“接口不支持时报错”处理，返回无 alpha 的立绘时先走透明底回退。
- 错误分类先看响应体里的错误代码，不只看 HTTP 状态码：`service_unavailable`、`overloaded`、`rate_limit` 这类即使状态码是 4xx 也按临时错误处理。

OpenAI 自家模型换代快（`gpt-image-1` 已于 2026-10-23 关闭，当前为 `gpt-image-2.5/2.6-{sunburst,flare}`），模型名只作配置项和示例，不写死默认。

## 4. 技术检查与占位图

技术检查只看这几项，不做审美检查：

- 能否解码。
- 尺寸是否正确：派生图（表情差分、背景变体）的尺寸必须和基准图完全一致，这是播放器换表情做混合的前提（见[播放器](./player.md)）；尺寸不符直接拦下。
- 主体是否完整。
- 构图与安全区用数值判断，不交给视觉模型：
  - 派生图和基准图的 alpha 外框（宽、高、中心）差值超过阈值就拦。
  - 表情差分只有头顶一小段轮廓轻微触边、与基准轮廓吻合时，先用基准图恢复这一小段，再检查透明度与外框；真实裁切仍拦。
  - CG 和背景另加一条：显著主体落在中央 4:3 安全区内的比例 ≥ 0.70。
- 透明底是否有效：第一道查 alpha 通道（有 alpha，且全透明像素占比 ≥ 0.5%），第二道查像素里有没有画出棋盘格。透明底失败常见于返回 RGB 图或将灰白棋盘格画入像素，第一道查 alpha 通道即可拦下绝大多数情况，像素检测用于兜底“有 alpha 但仍画了棋盘格”的情形。
- 背景变体不用像素相似度判断构图：换夜景会让全图亮度重映射，相似度失去意义。技术检查只卡尺寸一致，构图交给视觉审核的 `description` 项。

视觉审核在生图工具里执行，对照参考图和描述判断，输出结构化结果 `{pass, failedChecks, feedback}`：`failedChecks` 取 `identity`（画成别人）、`anchors`（锚点特征丢了）、`description`（和描述不符）、`style`（画风漂移）、`artifacts`（画面瑕疵）中的若干项，每项单独打分、单独定阈值，不合成总分。不通过时 `feedback` 由工具追加到画师重画提示词的尾部，让画师知道改哪里。

- `identity`：CG 拿去比对它所含角色的造型基准图（玩家看到的是立绘脸），不比对设定图。
- `anchors`：锚点特征（`anchorFeatures`，2–3 个）和主色（`keyColors`）逐项核对；表情差分审核先核锚点在不在，再看整体。
- `description`：核对剧本要点有没有画到——模型可能不拒绝但悄悄改掉关键内容（例如把“上吊”画成“蹲坐的女子”），画面合法但要素丢了也算不通过。
- `style`：没有角色身份参考图的造型基准图只按文字画风描述判定。仅从画风参考图得出的差异写入可选的 `styleReferenceFeedback`，不影响审核结果，也不追加到重画提示词。表情差分不传画风参考图给审核：表情是否到位按保存的描述判定，脸外的内容和画风按已接受的基准图核对；锚点或表情不符仍不通过。

图片最终失败的章节用占位图也能玩，并标“需要处理”。占位图分三类，由代码生成（sharp 画 SVG 转 WebP，灰底 + 图标 + “需要处理”字样）：**背景**和 **CG** 1920×1080，**角色** 1024×1536 竖版透明。导出 `.novelive` 作品包时会列出这些章节提醒创作者，但不阻止导出。

## 5. 单图重生成与过期提示

- **单图重生成**：在编辑器中可以重新生成单张图片，默认出一张直接替换，也可以手动要求多出几张来挑。
- **过期与连带提示**：上游设定或参考图变化后，受影响的图片标为“过期”，由创作者决定重画还是保留。重画上游素材时会提示连带关系，例如重画造型基准图时，提示它下面的表情要不要一起重画。剧情里的外貌变化不算上游变化，而是开新造型（见[设定集与术语表](./bible.md)）。
