# 视觉管线

说明视觉素材的层级组织、参考来源、生成要求、技术检查、占位图与过期重生成规则。

## 1. 素材层级

视觉素材分为三类：

- **角色**：`角色 → 造型 → 表情`
- **地点**：`地点 → 变体`
- **CG**：单独一类

同一系列的作品可以共享素材，下级的卷或作品可以覆盖（详见 [工程与作品格式](./work-format.md)）。不做骨骼动画和 Live2D。

## 2. 角色、参考来源与确认点

### 2.1 角色分类与立绘规范

- **可复用与一次性角色**：角色分为可复用角色和一次性角色。可复用角色先建完整参考，长期复用；一次性角色只画当前场景要用的，之后再出场时升级为可复用角色。
- **角色一致性**：造型基准图参考角色设定图（或上一套造型）重新画；表情从所在造型的基准图编辑派生，只改脸部，姿势和位置不变，播放器里换表情时立绘不跳。派生图没有透明通道或尺寸和基准图不一致时由技术检查拦下，画成别人时由视觉审核拿基准图对比拦下。
- **立绘构图与对齐**：立绘画膝上或半身，按头顶或腰线对齐。
- **表情**：新建角色时先登记一套基础表情，模型写剧本时用到新表情就直接登记；表情第一次在剧本里用到时才画（见[设定集与术语表](./bible.md)）。美术导演列图清单时做同义表情合并：未登记的表情先和已有表情比对，意思相同就改用已有的。表情差分始终从基准图编辑派生，不从另一张差分再派生：编辑误差会累积漂移。差分画师的内置提示词把表情名展开成眉、眼、嘴的动作描述（如 `angry` → 眉下压聚拢、眼睛眯起瞪视、咬紧牙关），不写情绪单词；keep-list（脸型、发型、瞳色、痣、发卡、服装、姿势、取景、画风等要保持的特征）由代码从角色外貌字段拆出传入，不让画师自己概括。外貌描述里的锚点特征（见[设定集与术语表](./bible.md)）同时给派生提示词和视觉审核用。

### 2.2 参考来源与确认点

参考来源分三种，不做联网搜图（以后可能做）：

1. 创作者提供的参考图。
2. EPUB 插图（EPUB 导入在 M4，此前该来源不可用）：由模型筛选后，作为候选放进“角色设定 / 主视觉”确认点。
3. AI 生成：没有参考时，AI 按书中描写出几版角色设定供创作者挑选（每个主要角色每套造型候选默认 3 版）。

“角色设定 / 主视觉”是制作流程的第一个确认点（见 [创作流水线](./creation-pipeline.md)），只覆盖第一卷的主要角色；其余角色第一次出场时，立绘画师按设定集描述直接画造型基准图，不停下确认。已经有参考图时是否停下确认，由作品设置里的开关决定。

### 2.3 出图分工

要画的图由三个画师分工，各自有内置提示词，自己调用生图工具，按技术检查和视觉审核的结论决定是否重画；一张图最多重画「生图失败重试次数」次（默认 3），用完用占位图并标“需要处理”：

- **立绘画师**（主模型）：造型基准图，竖版透明底。
- **场景画师**（主模型）：背景基准图和 CG，16:9，主体在 4:3 安全区。画黑暗场景（暴力、死亡）时默认用光影、剪影、留白表现，直白的描写交给剧本文字；降敏改写仍是审核被拒后的兜底。
- **差分画师**（快速模型）：表情差分和背景变体，从基准图编辑派生，只改一处。

所有画师调用都带上 `bible/style.json` 里的主视觉作参考图（统一画风，不能只存着不用），内置提示词里写明“必须参照参考图”。场景画师画 CG 时再加上出场角色的造型基准图和该地点的地点基准图（若有），提示词里写上角色外貌；CG 的参考图最多（主视觉 + 地点基准 + 各角色造型基准）约 4–6 张，在接口上限内。

要新画的图进入出图队列：同一张图只画一次，基准图画完它的差分才开始画，同时画的图不超过「同时出图数」（默认 8）。

生图工具传多张参考图时，由工具按派生类型在提示词头部生成每张图的角色声明句（如“第 1 张是主视觉，只参照画法、配色和细节密度，不照搬内容；第 2 张是 `lin-xiao` 的造型基准图”），模型不写这句。提示词的完整拼装见 2.4。

实测口径的成本：每张立绘约 0.049 美元、每张场景约 0.057 美元；100 章约 470–530 张图、约 23–30 美元，算上重画约 35–45 美元。单张出图耗时中位数 37 秒。

内容审核拒绝不算临时错误：先按降敏规则改写一次，再被拒才用占位图并标“需要处理”（见[创作流水线](./creation-pipeline.md)）。降敏规则写进画师内置提示词：去掉武器、血液、身体部位、年龄词等具象名词，改成光影、氛围、剪影描写，角色用外观特征不用年龄词；重画时由工具把固定句“上一次生成被内容审核拒绝，请收敛描写”追加到提示词尾部，不让画师自己猜往哪改。

审核拒绝的识别按各家报错形状归成一类：OpenAI `error.code=moderation_blocked`；火山 `error.code` 为 `Input|Output{Text,Image}SensitiveContentDetected.*` 一族；阿里百炼 `invalid_request_error` + `InvalidParameter` 且 message 含敏感或审核字样；Together、SiliconFlow 的 422 safety 命中；中转透传上游的 `error.code`/`message`，按关键字匹配。审核拒绝不耗 SDK 重试（SDK 本来就只重试 429、5xx 和连接错误，400 不重试）。

差分画师将来可以换本地或第三方编辑模型时，Qwen-Image-Edit 是备选记录（开源权重，支持多图一致性编辑），当前仍走 OpenAI 兼容图片接口（适配规则见「图片接口适配」一节）。

### 2.4 出图提示词

`draw_image { content }` 的提示词由工具拼装，画师只写其中的内容段（`content`）。让模型自由写整段提示词，出来的是图片模型的默认画风：细节过密、边缘碎、处处高光。

拼装顺序如下，拼成一段连续文字，不用 `Scene:`、`Subject:` 这类标签行（实测标签格式约束不了画风）：

1. **参考图声明**（代码）：逐张写明角色，见 2.3。
2. **素材类型句**（代码）：立绘、背景、CG、表情差分、背景变体各一句固定说明。
3. **内容段**（画师）：规则见下。视觉审核的 `feedback` 和审核拒绝的固定句由工具接在内容段之后。
4. **角色外貌**（代码）：立绘和 CG 从设定集外貌字段原文拼入，含锚点特征，画师不转述。
5. **画风描述**（代码）：`bible/style.json` 里的画风描述原文。
6. **构图与输出约束**（代码）：
   - 立绘：从头顶画到膝盖上方，腿在膝盖上方被画面底边裁断，人物居中，头顶留少量余量；透明背景，没有地面和影子；半透明边缘的颜色和相邻的衣服或皮肤一致。
   - 背景和 CG：主体在中央 4:3 区域，左右两侧只画延展配景；背景另写“空景，画面里没有人”。
   - 差分：只改一处，其余和第 1 张一致，并逐项列出 keep-list。
7. **渲染块**（代码，固定放在最后一行）：`large simple color masses, low visual frequency, restrained edge density, clear edge hierarchy, minimal internal contour lines, broad shadow shapes, suppress micro-texture and micro-contrast, no unnecessary specular highlights`。

固定句是 `creator` 包里的英文常量；内容段、外貌、画风描述用作品语言。实测内容段的语言、渲染块的语言对结果都没有显著影响。

画师写内容段的规则，写进画师内置提示词：

- 只写看得见的东西：在哪里、什么时间和天气、光从哪来；谁在做什么、什么姿势，表情写成眉、眼、嘴的动作；必须出现的物件最多三四样。用陈述句，不写“请画”“确保”。
- 不写画风、媒介、画质、构图和镜头词，这些由代码拼。工具查禁词，命中就退回改写。禁词包括 masterpiece、best quality、highly detailed、ultra detailed、intricate、8K、4K、photorealistic、award-winning、cinematic、杰作、高质量、细节丰富、精致、超清、电影感，以及任何画师名。
- 要排除的东西用正面说法写（“空无一人的院子”），不写否定句，也不加 `Avoid:` 行。实测加 `Avoid:` 行画面没有更干净，还让一张 CG 丢了“拉车”这个要点。
- 内容段不超过 150 字（英文约 100 词），超出由工具退回。
- 不添加描述和设定集里没有的人物、物件和情节。
- 重画时只改内容段里和 `feedback` 有关的那一句，其余原样保留；固定句每次由工具重新拼，画师改不到。

主视觉（确认点 1 的候选）也用同一套拼装和渲染块生成。主视觉画得太细，碎感会传给之后所有的图：第三轮的水彩主视觉作参考画出的 CG 和背景是全场最碎的，祥子在 CG 和立绘之间也认不出是同一个人。

接口参数：`quality` 用接口默认值，`complexity` 不传。实测 `complexity: low` 几乎没有效果；`quality: medium` 省约 24% 输出 token，画质略降。

## 3. 生成规则与本地处理

- **透明底**：立绘的透明底由图片模型直接输出，不做色键抠图。
- **画面内文字**：招牌、信件等画面里的文字由图片模型直接画，不做文字识别校验。
- **放大与降噪**：由放大程序负责（ncnn-vulkan 可执行文件，由创作端启动，走标准输入输出，不依赖 CUDA，三平台都有预编译版）。默认模型 Real-ESRGAN `realesrgan-x4plus-anime`，放大时一并去噪；另带一个快速档，设置页写明「低性能机用，画质下降」。默认把背景和 CG 放大到 2560×1440（2K），作品设置可选 4K；立绘放大到宽约 2048 像素（1024×1536 → 2048×3072），不按背景的倍数；差分和它的基准图必须用同一个放大模型，换档会跳清晰度。模型只出整数倍，到不了目标分辨率时先整数倍放大、再重采样到目标尺寸；透明立绘的 RGBA 整图送进模型，不拆通道。转 WebP、缩放、缩略图等其他图片处理在创作端进程里完成（进程划分见[系统架构](./architecture.md)）。
- **存储格式**：图片默认存为有损 WebP（质量 90，保留透明通道），应用设置里的全局开关可改无损。

## 3.1 画面规格

- **舞台**：以 16:9（1920×1080）为基准；各种横屏比例（16:10、4:3、手机横屏、21:9）统一铺满窗口、裁掉多出的部分，不留黑边；不做竖屏。
- **背景和 CG**：直接按 16:9 生成，提示词要求主体落在中间的 4:3 安全区、上下留余量；铺满裁切时主体不受影响。
- **立绘**：竖版、透明底。
- **背景变体**：同一地点的变体（白天、夜晚、雨天）从该地点的基准图编辑派生；播放器里变体之间默认硬切，交叉淡入淡出等实测之后再说。
- **模型能力**：设置页测试图片模型时依次试文生图、透明底、图片编辑三项，分别显示结果；不支持时只提示，制作时不做兜底，由创作者自己换模型。

## 3.2 图片接口适配

生图走 OpenAI 兼容图片接口，但各家实现不一样。应用不做能力探测：图片模型配置里除地址、API Key、模型名外，用户声明四项——协议形状（OpenAI images 协议 / 其他）、能否编辑（支持 / 仅文生图 / 不确定）、能否出透明底（支持 / 不支持 / 不确定）、尺寸怎么填（任意 `WxH` / 分辨率档位 / 固定枚举）。填地址时按域名自动套预设（OpenAI、Seedream、Qwen、Gemini 兼容、SiliconFlow、通用中转）；认不出的域名回退到通用 OpenAI 兼容声明。设置页的三项能力测试核对声明，对不上就提示矛盾，不阻止保存。

各家差异的精简对照：

| 接口 | 编辑 | 透明底 | 尺寸 | 返回 |
| --- | --- | --- | --- | --- |
| OpenAI（`gpt-image-2.5/2.6-{sunburst,flare}`） | `/edits` multipart，最多 16 张参考图 | `background:transparent` | 任意 `WxH` | 恒 `b64_json` |
| Seedream（火山方舟） | 无 `/edits`，图生图走 generations 的 `image` 字段 | 5.5 任意；5.0 图生限 1 张带 alpha 参考图 | `1K/1.5K/2K` 档或 `WxH`（有总像素区间） | 默认 `url`（24h） |
| Qwen（阿里百炼兼容模式） | 无 `/edits`，generations 传 `image` | 2.1 系按提示词自动出 alpha | `WxH`（512²–2048²） | 默认 `url`（24h），b64 仅 3.0 系 |
| Gemini 兼容 | 无 `/edits` | 不支持 | `extra_body.aspect_ratio` | `b64_json` |
| SiliconFlow | 部分模型（`image`/`image2`/`image3` 字段） | 不支持 | `image_size` 固定枚举 | `images[].url`（1h，非 `data[]`） |
| new-api / one-api 系中转 | 看渠道（透传或翻成 generations+image） | 看上游 | 透传上游语义 | 归一成 `data[]{url,b64_json}` |

适配层在 `draw_image` 内部做归一化：

- 画师只写内容段，不写反向提示词：图片模型没有 negative prompt 参数，写成 `Avoid:` 行实测无益（见 2.4）。各家原生的 `negative_prompt` 参数第一版不用。
- 没有 `/edits` 端点的接口，编辑请求降级为 generations + `image` 字段（Seedream、Qwen、部分中转走这条）。
- 返回 `url` 的下载成字节归一（Seedream、Qwen、Together 默认 url，SiliconFlow 只有 url）。
- 尺寸按声明的填法吸附到合法值：尺寸一律以像素给出，并按各家规则吸附到 16 的倍数。返回的尺寸可能和请求不同（实测编辑接口会跟着参考图的尺寸走，请求 1536×864 回来 1672×941 或 1536×1024）：宽高比差在 1% 以内就缩放到目标尺寸；超过 1% 就从中心裁成目标比例，再做安全区检查。主视觉生成后同样先裁成 16:9 再存。
- Seedream 恒传 `watermark:false`（默认会加“AI 生成”水印）。
- 声明要透明底、回来的图却没有有效 alpha，按技术检查失败拦下。
- 第一版不开生成过程预览（`stream` 只有 OpenAI、OpenRouter 和 Seedream 老型号支持）；OpenRouter 图片接口第一版不接（不是 `/v1/images/*` 形状）。
- Gemini 可以填，但它不能编辑也不能出透明底，做不了差分和立绘画师的模型。
- 错误分类先看响应体里的错误代码，不只看 HTTP 状态码：`service_unavailable`、`overloaded`、`rate_limit` 这类即使状态码是 4xx 也按临时错误处理。

OpenAI 自家模型换代快（`gpt-image-1` 已于 2026-10-23 关闭，当前为 `gpt-image-2.5/2.6-{sunburst,flare}`），模型名只作配置项和示例，不写死默认。

## 4. 技术检查与占位图

技术检查只看这几项，不做审美检查：

- 能否解码。
- 尺寸是否正确：派生图（表情差分、背景变体）的尺寸必须和基准图完全一致，这是播放器换表情做混合的前提（见[播放器](./player.md)）；尺寸不符直接拦下。
- 主体是否完整。
- 构图与安全区用数值判断，不交给视觉模型：
  - 派生图和基准图的 alpha 外框（宽、高、中心）差值超过阈值就拦。
  - CG 和背景另加一条：显著主体落在中央 4:3 安全区内的比例 ≥ 0.70。
- 透明底是否有效：第一道查 alpha 通道（有 alpha，且全透明像素占比 ≥ 0.5%），第二道查像素里有没有画出棋盘格。实测的透明底失败全是返回 RGB 图、把灰白棋盘格画进像素，由第一道拦下；像素检测只在“有 alpha 但还是画了棋盘格”的情形起作用。
- 背景变体不用像素相似度判断构图：换夜景会让全图亮度重映射，相似度失去意义。技术检查只卡尺寸一致，构图交给视觉审核的 `description` 项。

视觉审核在生图工具里执行，对照参考图和描述判断，输出结构化结果 `{pass, failedChecks, feedback}`：`failedChecks` 取 `identity`（画成别人）、`anchors`（锚点特征丢了）、`description`（和描述不符）、`style`（画风漂移）、`artifacts`（画面瑕疵）中的若干项，每项单独打分、单独定阈值，不合成总分。不通过时 `feedback` 由工具追加到画师重画提示词的尾部，让画师知道改哪里。

- `identity`：CG 拿去比对它所含角色的造型基准图（玩家看到的是立绘脸），不比对设定图。
- `anchors`：锚点特征（`anchorFeatures`，2–3 个）逐项核对；表情差分审核先核锚点在不在，再看整体。
- `description`：核对剧本要点有没有画到——模型可能不拒绝但悄悄改掉关键内容（例如把“上吊”画成“蹲坐的女子”），画面合法但要素丢了也算不通过。

图片最终失败的章节用占位图也能玩，并标“需要处理”。占位图分三类，由代码生成（sharp 画 SVG 转 WebP，灰底 + 图标 + “需要处理”字样）：**背景**和 **CG** 1920×1080，**角色** 1024×1536 竖版透明。导出 `.novelive` 作品包时会列出这些章节提醒创作者，但不阻止导出。

## 5. 单图重生成与过期提示

- **单图重生成**：在编辑器中可以重新生成单张图片，默认出一张直接替换，也可以手动要求多出几张来挑。
- **过期与连带提示**：上游设定或参考图变化后，受影响的图片标为“过期”，由创作者决定重画还是保留。重画上游素材时会提示连带关系，例如重画造型基准图时，提示它下面的表情要不要一起重画。剧情里的外貌变化不算上游变化，而是开新造型（见[设定集与术语表](./bible.md)）。
