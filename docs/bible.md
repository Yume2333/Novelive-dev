# 设定集与术语表

说明设定集和术语表包含哪些内容、各字段的含义、设定随剧情变化的记法、候选条目的使用规则，以及全书预览结果的存放方式。

## 用途

- 模型写剧本时，靠它保持人物和设定前后一致。
- 图片模型画角色和地点时，从这里取描述。
- 创作者和 Agent 在对话面板里讨论、修改。

## 通用规则

- **格式**：JSON，由 pi-schema 定义。
- **语言**：描述文字用作品语言写，跨语言制作时就是目标语言。图片提示词在生成图片时由模型根据设定集组织。
- **状态**：每个条目分“候选”和“已确认”两种，并记下是从哪一章提取的。
- **层级**：系列、卷、作品三层按条目整条覆盖（见[作品格式与工程](./work-format.md)）。
- **加入已有系列**：导入新原文加入已有系列时，它成为该系列的新一卷。全书预览照常跑新原文；按卷综合不从头生成，而是在系列已有设定集上增量更新——产出设定补丁，逐条标新增、更新或不变。已有角色的造型和素材直接复用，新角色和变化条目照常走候选规则。
- **章节引用**：用章节 ID 引用章节，先后顺序按系列内的章节顺序算。

## 设定随剧情变化

角色、关系、地点条目都有一个“变化”列表，每一项写明从哪一章起、哪个字段、变成什么。字段分两类：“固定”字段（发色、本名这类不会变的）和“会变”字段（身份、职位这类随剧情变的）；不同值出现在“会变”字段记成变化，出现在“固定”字段才算和已确认版本冲突。

每个条目还记“第几章揭示”（`revealedChapter`，M1a 起），表示读者最早在哪一章能知道这件事——它往往比首次出场晚（称号、秘密身份这类）；没填时按首次出场算。

模型写第 N 章时，只拿到截至第 N 章的设定：

- 揭示章在第 N 章之后的条目不给。
- “变化”只应用到第 N 章为止。
- 时间线只给到第 N 章。
- 伏笔只给第 N 章及以前埋下的，状态按第 N 章时算。

这样模型不会被后面的剧情剧透，也不会把后期的发型画到前期的立绘上。有两个例外：一是写手按作者视角工作，能看到全书梗概（到当前卷为止）和本卷剧情骨架，方便埋伏笔；提示词用“可知性边界”约束（作者知道的秘密不等于人物已经知道、计划终点不是本章必须完成的目标、未附的全书剧情保持未知）。二是原文引文证据（`evidence[].quote`）到 M2 才加，届时审稿和冲突说明可以直接引用，不用再翻原文。

**外貌变化开新造型**：外貌在某一章变了（比如剪了短发），就从这一章起开一个新造型（如 `uniform-short-hair`）。旧造型的图在之前的章节照用，新造型的图第一次用到时再画。外貌的变化只作用于之后新开的造型，已经画好的图不会因此被标成过期。

## 设定集

### 角色

| 字段 | 内容 |
| --- | --- |
| ID | 素材名，如 `lin-xiao` |
| 名字 / 原文名字 / 别名 | 作品里的写法、原文写法和其他叫法 |
| 称呼 | 谁怎么叫这个角色，比如“学姐”“大小姐”“那家伙” |
| 身份 | 身份和在故事里的定位 |
| 性格 | |
| 说话方式 | 自称、口癖、语气 |
| 外貌 | 画立绘用的外貌描述，带 `anchorFeatures` 子字段：2-3 个锚点特征（痣、发饰、瞳色这类），确认点 1 定稿角色时写，供派生图的“其余保持”清单和视觉审核对照 |
| 造型 | 每套造型的 ID、描述，以及从哪章开始穿 |
| 表情 | 已登记的表情 |
| 参考图 | |
| 可复用 / 一次性 | 见[视觉素材](./visuals.md) |
| 首次出场 | 章节 |
| 知道什么（knows） | 这个角色第几章知道了什么，整理预览时顺带提取；写手和审稿据此判“他怎么会知道”这类崩坏 |
| 变化 | 见上文“设定随剧情变化” |

**表情**：新建角色时先登记一套基础表情（平静、开心、生气、悲伤、惊讶、害羞等）。模型写剧本时用到新表情就直接登记，不需要确认。表情都是第一次在剧本里用到时才画，登记时不画。美术导演列图清单时做同义表情合并：未登记的表情先和已有表情比对，意思相同就改用已有的，不登记新表情。

### 角色关系

记录谁和谁是什么关系，带“变化”列表。

### 地点

| 字段 | 内容 |
| --- | --- |
| ID | 素材名，如 `classroom` |
| 名字 / 原文名字 | |
| 描述 | 画背景用的外观描述 |
| 变体 | 每个变体的 ID 和描述，比如白天、夜晚、雨天 |
| 参考图 | |
| 首次出现 | 章节 |
| 变化 | |

### 剧情骨架

每卷一份，写这一卷的主线概要。

### 时间线

故事内的关键事件按时间排列，每条写事件、故事内的时间和发生在哪一章。

### 伏笔

每条写伏笔内容、在哪章埋下、在哪章回收、现在还开着没有。写剧本时提醒模型不要提前揭晓，也不要漏掉回收。代码侧两条把关：登记时单章最多收约 2 条，防止模型把每个未解释名词都报成伏笔；渲染进上下文时，还没回收的常驻伏笔按埋设早晚排序、最多给 12 条，埋下超过 30 章还没回收的标“该收了”。

### 风格

画风描述和风格参考图（即主视觉），以及旁白语气。主视觉不是只存着：所有画师调用都把它作为参考图带上（见[视觉素材](./visuals.md)）。

### 素材登记表

一张表登记作品里全部视觉素材的 ID，写手、美术导演、画师、编译器、播放器都只认这张表。文件是 `assets/asset-registry.json`，位置和 ID 写法见[作品格式与工程](./work-format.md)：

| 字段 | 内容 |
| --- | --- |
| ID | 素材名：地点 `place/variant`，角色 `character/costume/expression`，CG `cg-<id>` |
| 类型 | 立绘 / 背景 / CG / 表情差分 / 背景变体 |
| 状态 | 已画 / 待画 / 占位 |
| 同义合并 | 表情同义合并（见[视觉素材](./visuals.md)）的归并结果也登记在这里 |

校验时分两头查：说话人 ID 查设定集的角色表，舞台素材 ID 查这张登记表。

### 不放进设定集的内容

CG 不放进设定集。一张 CG 一般只在一个场景里用，描述记在所在章节的 `chapter.json` 里。

## 术语表

术语表管角色名、地名以外的专名：组织、物品、招式、称谓、口头禅、文化表达等。角色名和地名只记在设定集的角色和地点条目里，同一个名字只记一处。

| 字段 | 内容 |
| --- | --- |
| 原文写法 | |
| 作品里的写法 | 同语言制作时和原文相同 |
| 注音 | 模型加注音时照这个写，保证同一个词前后读音一致 |
| 类别 | 组织、物品、招式、称谓、口头禅、文化表达等 |
| 备注 | 用法说明，比如“只有主角这样叫她” |

## 候选条目的使用

综合时新提取的条目先作为候选：

- **不冲突**：和已确认设定不冲突的候选直接用于制作，创作者事后再确认或修改。
- **冲突**：和已确认设定冲突时，制作继续用已确认的版本；冲突列在设定集里等创作者处理，不阻塞制作。

## 文件布局

```text
bible/
  style.json                 风格（含主视觉）
  characters/<角色>.json
  relations.json
  locations/<地点>.json
  timeline.json
  foreshadowing.json
glossary.json
```

这套结构在系列、卷、作品三层都可以有。剧情骨架按卷存在 `volumes/<卷 ID>/bible/skeleton.json`。

卷摘要（digest）存 `volumes/<卷 ID>/bible/digest.json`；全书梗概由各卷 digest 现拼，不单独存。

## 全书预览结果

全书预览的逐章结果（剧情摘要、出场人物、地点、时间线线索、伏笔）存在 `source/preview/<章节 ID>.json`，一章一个，格式用 pi-schema 定义：

- 每章只写一次、之后几乎不改，所以存成普通文件，不进 SQLite。
- 它是从原文提取的，跟着原文走：导出时选了带原文才带上。
- 综合、Agent 重做章节和对话时可以读取。
