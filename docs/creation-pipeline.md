# 创作流水线

说明小说从导入、全书理解、剧本改编到调度、停止恢复与编辑修改的完整流程。

## 1. 导入与全书理解

原文支持 TXT、EPUB、Markdown、DOCX、PDF，工程内保留 `系列 → 卷 → 作品 → 章节` 层级，支持数百上千章的长篇作品（工程结构见 [工程与作品格式](./work-format.md)）。

导入后有一个可以直接跳过的向导步骤，用于核对作品信息和章节划分，这一步不算确认点。原文没有分卷时，整理角色在这一步按剧情段落建议分卷，创作者可以修改，也可以跳过直接用建议。

**全书预览**由快速模型逐章读完全部正文，可并行推进。每章产出剧情摘要、出场人物、地点、时间线线索和伏笔；超长章节切段预览，不截断。

综合与制作都按卷推进：第一卷的预览和综合完成就开始制作该卷，后面各卷的预览和综合在后台继续。综合按卷产出剧情骨架、设定集和术语表（字段见[设定集与术语表](./bible.md)）。新提取的设定条目先作为候选，不冲突的直接用于制作；和已确认的设定冲突时不覆盖，制作继续用已确认的版本，冲突等创作者处理，不阻塞制作。

## 2. 确认点

创作过程中只有两个确认点：

1. **角色设定 / 主视觉**：确定第一卷主要角色与视觉参考，只出第一卷主要角色的设定候选；其余角色第一次出场时由立绘画师按设定集直接画，不停下（详见 [视觉管线](./visuals.md)）。已经有参考图时是否停下确认，由作品设置里的开关决定。
2. **第一章成品**：创作者可以试玩，也可以进编辑器修改；手动点击“继续制作”后，其余章节在后台按卷连续制作。

作品停在确认点等创作者处理时让出制作槽，排在后面的作品先做；创作者确认后，这部作品排回队首。

## 3. 改编控制与原则

创作者通过两组三档预设、自由文本和规则控制改编结果：

| 控制项 | 选项与默认值 | 作用域与规则 |
| --- | --- | --- |
| 改编强度 | 忠实 / 平衡（默认）/ 精简 | 作品级预设 |
| 演出密度 | 宽松 / 标准（默认）/ 激进 | 作品级预设 |
| 改编要求 | 自由文本 | 作品级设定 |
| 规则 | 在编辑时把修改存为规则 | 作用域为本章或本作品；本章规则优先于本作品规则，新规则只影响还没开始的任务 |

改编遵循以下原则：

- 保留对白原意和口吻。
- 动作和表情转成演出。
- 长段环境描写压成短旁白，必要的旁白保留。
- 不加原作没有的情节。

改编时模型可以给文字加文本标记、注音、句中停顿和变速（文本能力见[播放器](./player.md)）。模型也可以提议新的自定义标记，创作者确认后才生效。

跨语言制作只走“直接生成目标语言剧本”这一条路。人名、地名的统一写法记在设定集的角色和地点条目里，术语表负责统一其余专名的译法。

## 4. 调度、停止与恢复

### 4.1 队列与章节推进

- **章节优先**：第一章优先制作；作品内部，创作者可以把某几章设为优先。优先章节的上一章还没写时，写手用上一章的全书预览摘要衔接；上一章写完后不回头改这一章。
- **单章流程**：每章三步加一个出图阶段，每步做完都存下来，停下后从没做完的一步接着做：
  1. **写**：写手一章写一次，自己分场，每场写上场景标题和对应的原文段落；章太长时按段落切成几段依次写。
  2. **审稿**（作品开关，默认关）：审稿列出有把握的问题，写手按问题改一遍，改完不再复审。
  3. **演出与图清单**：美术导演读整章剧本，补背景、镜头、CG 等演出，列出本章要用的图清单（已有的、要新画的，各带一句描述），并做同义表情合并。
  4. **出图**：清单里要新画的图进入出图队列，按素材排：同一张图只画一次，基准图画完它的差分才开始画。三个画师分工画（立绘画师画造型基准图，场景画师画背景和 CG，差分画师画表情差分和背景变体；分工见 [视觉管线](./visuals.md)），同时画的图不超过设置里的「同时出图数」（默认 8）。每张图经生图工具内的技术检查和视觉审核，不通过时由画师换提示词重画，最多重画「生图失败重试次数」（默认 3）次，用完用占位图并标“需要处理”。每张通过检查的图立即保存；停止后重跑时跳过已有的图，只补没画完的。一章要用的图都齐了这章就发布。
- **写和画重叠**：写手写下一章时，上一章在出图；写手仍一章接一章写，衔接用上一章剧本的结尾。
- **章节完成与占位图**：一章的图都齐即为“已发布”，自动可玩（第一章要先过确认点 2）。图片最终失败的章节用占位图也能玩，并标“需要处理”。占位图分三类：角色、背景、CG。导出 `.novelive` 作品包时会列出这些章节提醒创作者，但不阻止导出。

### 4.2 停止、错误与退出恢复

- **立即停止**：停止只有这一种方式，会取消排队任务并中断正在跑的请求。下次继续时，把被中断的任务重新执行一遍。
- **临时错误**：遇到网络、限流或服务临时出错时，只用 SDK 或 Agent 底座自带的重试，不自己另做重试；失败就停下，标“需要处理”。
- **图片被内容审核拒绝**：不算临时错误。让模型把提示词改得含蓄一点再试一次，还被拒才用占位图，标“需要处理”。
- **关闭与退出**：关窗口后缩到托盘，制作继续；真正退出时如果还有任务在跑，询问创作者。
- **崩溃恢复**：崩溃或异常退出后重新打开，制作保持停止状态，创作者确认后才继续。
- **系统通知**：只在停在确认点等待处理、有任务需要处理、整部作品做完这三种情况发送。

## 5. Novelive Agent 与对话面板

创作由 **Novelive Agent** 驱动，Agent 底座用 pi。Agent 分成几个角色，各自用对应的模型：

| 角色 | 默认模型 | 负责 |
| --- | --- | --- |
| 整理 | 快速模型 | 全书预览、卷内摘要汇总、压缩摘要、导入时核对章节和作品信息（无分卷时建议分卷）、会话标题、把修改总结成规则 |
| 主控 | 主模型 | 按卷综合、设定冲突说明、对话面板 |
| 写手 | 写作模型 | 写剧本正文、分场；不用工具 |
| 美术导演 | 主模型 | 补演出、列出本章要用的图清单、做同义表情合并 |
| 立绘画师 | 主模型 | 画造型基准图（竖版透明底），调用生图工具 |
| 场景画师 | 主模型 | 画背景基准图和 CG（16:9，主体在安全区），调用生图工具 |
| 差分画师 | 快速模型 | 画表情差分和背景变体（从基准图编辑派生，只改一处），调用生图工具 |
| 视觉审核 | 视觉模型 | 在生图工具里看图、筛选 EPUB 插图 |
| 审稿 | 主模型 | 作品开关，默认关；对照原文和设定集找剧本问题 |


- **写手预设**：文风说明、输出约束、可选的采样参数和输出替换规则（解析剧本前清理模型输出）。应用有一个全局默认预设，作品可以改选别的预设或在默认上改几项。其他角色的提示词内置，不开放修改。

作品级对话面板支持创作者与 Agent 讨论，让 Agent 修改设定集、术语表、改编要求，或发起工作流（重做章节、重写场景、重画图片、重新综合某卷）：

- Agent 提出的所有修改和要发起的工作流先列给创作者，确认后才生效。
- 重做的章节进入制作队列。
- 聊天按会话组织，每部作品可以有多个会话；改写一条消息后重新发送会形成分支。会话保存在工程里，过长时较早的内容压缩成摘要。
- 只有对话面板里的主控能派子 Agent，子 Agent 不能再派。


## 6. 模型配置与用量统计

创作者自己准备五个模型：**快速模型**、**主模型**、**写作模型**、**视觉模型**和**图片模型**。每个角色有默认对应的模型，高级设置里可以单独给某个角色换模型。每个文本模型都要有上下文长度：能从 Agent 底座的内置模型目录查到就自动填，查不到由创作者填。

- 图片模型只接 OpenAI 兼容的图片接口，可以填自定义地址。图片模型设置里还有两项：「同时出图数」限制同时画的图，默认 8；「生图失败重试次数」是一张图在技术检查或视觉审核不通过后最多重画几次，默认 3，用完用占位图并标“需要处理”。
- 文本模型填接口格式（OpenAI Chat Completions、OpenAI Responses、Anthropic Messages）、接口地址、模型名和 API Key，通过 Agent 底座调用；文本调用不限并发，制作的并发来自角色分工和出图队列。
- API Key 简单加密后存在应用的配置文件里，方便备份和迁移。

用量统计面板按作品、阶段、模型和时间（天 / 月）统计，能拿到单价时显示参考金额。统计结果只作参考，不设预算，不做开工前估算，也不会自动停止。

## 7. 编辑器背后的修改

创作者可以在编辑器中修改已生成的内容（界面与交互见 [界面与流程](./ux.md)）：

- 直接修改台词和旁白，或替换角色表情。
- 让 Agent 重写单个场景，结果先以差异列表展示，勾选后再应用。
- 原文对照显示当前场景对应的原文段落，原文和场景可以双向跳转；选中一段原文可以直接让 Agent 按它改。
- 单张图重新生成，默认出一张直接替换，也可以手动要求多出几张来挑。
- 把修改存为规则。

修改立即生效，可以撤销，有修改历史。逐条调整演出的时间线编辑器以后再做。
