# 创作流水线

说明小说从导入、全书理解、剧本改编到调度、停止恢复与编辑修改的完整流程。

## 1. 导入与全书理解

原文支持 TXT、EPUB、Markdown、DOCX、PDF，工程内保留 `系列 → 卷 → 作品 → 章节` 层级，支持数百上千章的长篇作品（工程结构见 [作品格式与工程](./work-format.md)）。TXT 章节识别用规则表 `{name, pattern, kind: chapter|volume|exclude, example, enable}`（规则数据模型参考 TRNovel；规则内容是受 legado 默认目录规则集启发后自己写的，不照搬原文）：多条启用的 `chapter` 规则逐个试算，取命中数最多的一条作为主规则；序章、楔子、番外、后记、凡例这类无编号辅助标题和主规则是并存关系，它们的命中与主规则取并集，不参与竞争；裸数字标题至少命中 3 次才参选；带省略号和页码的目录行一律排除；`第X卷/部`、`上中下卷` 这类行标 `kind: "volume"`（`本 / 折` 体例也收录：卷级含 `第X本`，章级含 `第X折`），在导入向导里作为分卷建议给整理角色；识别出 2 个以上卷、但一章都没有时，把卷降成章（卷内本就更细的标题都没有，整卷作一章正是期望行为）。第一个标题之前的内容当“前言”章；全文一个标题都没有时，整本作为一章“正文”；章超过 `MAX_CHAPTER_CHARS`（20000 字）按段落边界再分，切出的章标题加“（N）”。规则无法保证覆盖全部异形排版，因此导入向导核对章节划分这一步不能省。TXT 编码识别覆盖 `utf-8 | gb18030 | big5 | shift_jis | utf-16le | utf-16be`，检测顺序：BOM → 纯 ASCII 直通 → UTF-16 字节嗅探（无 BOM 的 UTF-16 靠相邻字节对判定）→ 逐个编码严格解码（`TextDecoder` fatal）→ 质量门 → 书写系统密度打分 → 中文散文形状门；不用 chardet / jschardet。判为歧义时，导入向导列出至多 3 种候选编码，各显示解出的前几行让创作者选。EPUB 章识别按 nav → NCX →（h1/h2 + 关键词）→（spine 每个 entry 一章）的兜底链逐层回落。导入管线带固定的净化步：内置常见水印正则（书源名、网址、`www.`、`请收藏`、域名行、分隔装饰行），并识别原书的注释、脚注、版权页这类非正文段——从正文里剔除，存成章的附注，不参与覆盖，也不进剧本；每部作品可再加自定义规则。

导入后有一个可以直接跳过的向导步骤，用于核对作品信息和章节划分，这一步不算确认点。原文没有分卷时，整理角色在这一步按剧情段落建议分卷，创作者可以修改，也可以跳过直接用建议。M1a 没有界面：原文没有分卷先按整本一卷建工程，有 `kind: "volume"` 的卷标题时按卷标题分卷；核对结果由整理角色直接写进 `source/` 下的导入报告文件，核对向导（含分卷修改）在 M1b 读这份报告给创作者改（加入已有系列在 M4）。

**全书预览**由快速模型逐章读完全部正文，可并行推进。每章产出剧情摘要、出场人物、地点、时间线线索和伏笔；超长章节切段预览，不截断。

综合与制作都按卷推进：第一卷的预览和综合完成就开始制作该卷，后面各卷的预览和综合在后台继续。综合按卷产出剧情骨架、设定集和术语表（字段见[设定集与术语表](./bible.md)）。新提取的设定条目先作为候选，不冲突的直接用于制作；和已确认的设定冲突时不覆盖，制作继续用已确认的版本，冲突等创作者处理，不阻塞制作。

导入时也可以选“加入已有系列”：新原文作为该系列的新一卷，卷里一部作品，适合续作和第二部。这时全书预览照常跑新原文，按卷综合在系列已有设定集上增量更新——产出设定补丁（单卷内部综合可用新增、更新、删除、不变，加入已有系列时只用新增、更新、不变，不删系列已有条目）；已有角色的造型和素材直接复用，不重画。

## 2. 确认点

创作过程中只有两个确认点：

1. **角色设定 / 主视觉**：确定第一卷主要角色与视觉参考，只出第一卷主要角色的设定候选；其余角色第一次出场时由立绘画师按设定集直接画，不停下（详见 [视觉管线](./visuals.md)）。已经有参考图时是否停下确认，由作品设置里的开关决定。
2. **第一章成品**：创作者可以试玩，也可以修改 `work.json` 里的作品设置或让 Agent 重做该章（编辑器在 M2）；手动点击“继续制作”后，其余章节在后台按卷连续制作。

作品停在确认点等创作者处理时让出制作槽，排在后面的作品先做；创作者确认后，这部作品排回队首（`queue_pos` 取当前排队作品的最小值再减一，不打断正在制作的作品，从下一部作品开始前生效）。

## 3. 改编控制与原则

创作者通过两组三档预设、自由文本和规则控制改编结果：

| 控制项 | 选项与默认值 | 作用域与规则 |
| --- | --- | --- |
| 改编强度 | 忠实 / 平衡（默认）/ 精简 | 作品级预设 |
| 演出密度 | 宽松 / 标准（默认）/ 激进 | 作品级预设 |
| 改编要求 | 自由文本 | 作品级设定 |
| 规则 | 在编辑时把修改存为规则 | 作用域为本章或本作品；本章规则优先于本作品规则，新规则只影响还没开始的任务 |

改编强度三档的数值定义（目标句长写进写手提示词，只是节奏建议；长度检查规则见 [作品格式与工程](./work-format.md)）：

| 档位 | 一段原文 → 句子 | 目标句长 |
| --- | --- | --- |
| 忠实 | 按原句顺序拆成多句，保留原句顺序 | — |
| 平衡（默认） | 写成 1 到 3 句，长描写压短 | 30–70 字 |
| 精简 | 可以压成 0 到 2 句短旁白（仍算覆盖了这一段） | 15–45 字 |

三档都不设单句硬上限：句子装不进对话框时由播放器分页显示，剧本检查只给警告。

改编强度、演出密度等作品设置随时可改；改动只影响还没开始的任务，进行中的任务按改之前的设置跑完。

改编要求里可以写“红线”：违反即整章作废的可检查断言（比如“主角全程不能说话”）。红线在改编设置里置顶渲染、结尾再强调一次；内容人工必审。

改编遵循以下原则：

- 保留对白原意和口吻。
- 动作和表情转成演出。
- 长段环境描写压成短旁白，必要的旁白保留。
- 不加原作没有的情节。

改编时模型可以给文字加文本标记、注音、句中停顿和变速（文本能力见[播放器](./player.md)）。模型也可以提议新的自定义标记，创作者确认后才生效。

跨语言制作只走“直接生成目标语言剧本”这一条路（跨语言制作在 M4）。人名、地名的统一写法记在设定集的角色和地点条目里，术语表负责统一其余专名的译法。

## 4. 调度、停止与恢复

### 4.1 队列与章节推进

- **章节优先**：第一章优先制作；作品内部，创作者可以把某几章设为优先。优先章节的上一章还没写时，写手用上一章的全书预览摘要衔接；上一章写完后不回头改这一章。等优先章节上一章写完的章，状态词为“等待”并在面板上注明“等上一章”。
- **单章流程**：每章三步加一个出图阶段：写、审稿、演出与图清单，然后按素材队列出图；每步做完都存下来，停下后从没做完的一步接着做。步骤显示词固定为 写 / 审稿 / 演出 / 出图；“审稿”步含忠实度检查（默认开）与文风审稿（默认关）两档，两档都关时该步显示为跳过。
  1. **写**：写手一章写一次，自己分场，每场写上场景标题和对应的原文段落；章太长时按段落切成几段依次写。第三人称的心理描写要标成 `(inner)` 时必须改写成第一人称，否则留作旁白。
  2. **审稿**：分两档。忠实度检查默认开、可以关，只查漏段、加戏、对白改写、说话人归属错、独白降级、顺序不连贯、设定冲突，每条问题必须引用原文段落（引的是原文，与设定集的 `evidence[].quote` 无关）、由代码核对引文确实在原文里；文风审稿是作品开关、默认关，只评文笔，不评情节结构。两档都不循环：写手按问题改一遍，改完不再复审，返修后该章直接进演出步，步骤状态记为“演出”。
  3. **演出与图清单**：美术导演读整章剧本，补背景、镜头、CG 等演出，列出本章要用的图清单（已有的、要新画的，各带一句描述），并做同义表情合并。
  4. **出图**：清单里要新画的图进入出图队列，按素材排：同一张图只画一次，基准图画完它的差分才开始画。三个画师分工画（立绘画师画造型基准图，场景画师画背景和 CG，差分画师画表情差分和背景变体；分工见 [视觉管线](./visuals.md)），同时画的图不超过设置里的「同时出图数」（默认 8）。每张图经生图工具内的技术检查和视觉审核，不通过时由画师换提示词重画，最多重画「生图失败重试次数」（默认 3）次，用完换占位图——占位图也算图齐，该章以“已发布”加“需要处理”标记发布。每张通过检查的图立即保存；停止后重跑时跳过已有的图，只补没画完的。一章要用的图都齐了这章就发布。
- **写和画重叠**：写手写下一章时，上一章在出图；写手仍一章接一章写，衔接用上一章剧本的结尾。
- **章节完成与占位图**：一章的图都齐即为“已发布”，自动可玩（第一章要先过确认点 2；过确认点 2 之前第一章就按“已发布”显示、可以玩，停顿由作品级状态 `confirm-first` 表达）。图片最终失败的章节用占位图也能玩：状态仍是“已发布”，只是带上“需要处理”标记，处理完去掉标记。所有章都已发布就算作品完成，带不带标记都一样。占位图分三类：角色、背景、CG。导出 `.novelive` 作品包时会列出这些章节提醒创作者，但不阻止导出。

### 4.2 停止、错误与退出恢复

- **立即停止**：停止只有这一种方式，会取消排队任务并中断正在跑的请求。下次继续时，把被中断的任务重新执行一遍。
- **临时错误**：遇到网络、限流或服务临时出错时，文本和视觉调用两层重试：第一层在我们包的 `streamFn` 里统一传 `maxRetries: 2`，管响应头到达前的失败；第二层在 `streamFn` 外包一层整条消息重发，管流到一半断开、空回复、网关返回 200 后掉线，只在这条消息还没产生工具副作用时重发，最多 2 次；流式输出加空闲超时（事件级看门狗，阈值定稿见 `.workflow/research/pi-scaffolding.md`），超时按临时错误处理；用户取消不进任何重试。图片调用用 `openai` SDK 自带的默认重试；错误分类先看响应体里的错误代码（`service_unavailable`、`overloaded`、`rate_limit` 这类即使状态码是 4xx 也按临时错误处理），不只看 HTTP 状态码。重试用完就停下，标“需要处理”。
- **章节失败**：一章最终失败时整部作品暂停（写手要接上一章的结尾，不能跳过它往下写）：已经派出的图任务跑完，还没开始的章任务挂起，失败的章保持原状态并标“需要处理”；这种暂停不会被之后的停止、崩溃或确认动作覆盖，只有对失败章本身点重试才能解除。行内重试把该章排回章管线头部，成功后整部作品自动继续制作。
- **内容审核拒绝**：不算临时错误、不消耗重试次数。写手那一章先按降敏规则改写一次再写（保留情节和段落覆盖），还被拒就标“需要处理”；图片让画师按降敏规则改提示词再生成一次，还被拒才用占位图，标“需要处理”。
- **制作槽**：“同一时间只制作一部作品”只约束章管线和出图；逐章预览和按卷综合不占制作槽，后台照常跑。“继续制作”只恢复本作品被中断、被取消的任务；作品每次拿到制作槽时，都顺带恢复自己名下被中断的任务。对还没做完的章发起“重做本章”直接拒绝（在提议时就不接受，不进队列）。
- **写入前核对输入**：写剧本、综合设定、出图这类任务开始时记下所用原文和设定的哈希，落盘前重新算一遍；变了就不写入，这条运行记录状态为 `needs_attention`（`error_type='input_changed'`），界面上标“输入已改，需要重跑”。标“输入已改”的任务由创作者在制作面板点重跑（按当前最新输入跑），或随下一次继续制作自动重跑。
- **关闭与退出**：关窗口后缩到托盘，制作继续；真正退出时如果还有任务在跑，询问创作者。
- **崩溃恢复**：崩溃或异常退出后重新打开，制作保持停止状态，创作者确认后才继续。
- **系统通知**：只在四种情况发送——停在确认点等待处理、有任务需要处理、整部作品做完、播放器在后台等待本机连载新章。

## 5. Novelive Agent 与对话面板

创作由 **Novelive Agent** 驱动，Agent 底座用 pi。Agent 分成几个角色，各自用对应的模型：

| 角色 | 默认模型 | 负责 |
| --- | --- | --- |
| 整理 | 快速模型 | 全书预览、卷内摘要汇总、压缩摘要、导入时核对章节和作品信息（无分卷时建议分卷）、会话标题、把修改总结成规则 |
| 主控 | 主模型 | 按卷综合、设定冲突说明、对话面板（伏笔登记与渲染规则见 [设定集与术语表](./bible.md)） |
| 写手 | 写作模型 | 写剧本正文、分场；不用工具 |
| 美术导演 | 主模型 | 补演出、列出本章要用的图清单、做同义表情合并 |
| 立绘画师 | 主模型 | 画造型基准图（竖版透明底），调用生图工具 |
| 场景画师 | 主模型 | 画背景基准图和 CG（16:9，主体在安全区），调用生图工具 |
| 差分画师 | 快速模型 | 画表情差分和背景变体（从基准图编辑派生，只改一处），调用生图工具 |
| 视觉审核 | 视觉模型 | 在生图工具里看图、筛选 EPUB 插图 |
| 审稿 | 主模型 | 两档：忠实度检查默认开（漏段/加戏/对白改写/归属错/独白降级/顺序不连贯/设定冲突，引文由代码验真）；文风审稿是作品开关、默认关，只评文笔 |


- **写手预设**：内置可选风格块（视角、叙事风格、节奏、情感策略各选一项，块文本应用内置），外加文风说明自由文本、输出约束、可选的采样参数和输出替换规则（解析剧本前清理模型输出）；自由文本可以覆盖风格块。应用有一个全局默认预设（=一组默认风格块），作品可以改选别的预设或在默认上改几项。其他角色的提示词内置，不开放修改。

作品级对话面板支持创作者与 Agent 讨论，让 Agent 修改设定集、术语表、改编要求，或发起工作流（重做章节、重写场景、重画图片、重新综合某卷）：

- Agent 提出的所有修改和要发起的工作流先列给创作者，确认后才生效。
- 重做的章节进入制作队列。
- 聊天按会话组织，每部作品可以有多个会话；改写一条消息后重新发送会形成分支。会话保存在工程里，过长时较早的内容压缩成摘要。
- 只有对话面板里的主控能派子 Agent，子 Agent 不能再派。

工具循环角色（美术导演、审稿、主控、子 Agent）有请求次数软预算，数值用测试用书校准，超预算先提醒、再硬停，停不下来的标“需要处理”；画师只数重画次数。


## 6. 模型配置与用量统计

创作者自己准备五个模型：**快速模型**、**主模型**、**写作模型**、**视觉模型**和**图片模型**。每个角色有默认对应的模型，高级设置里可以单独给某个角色换模型。每个文本模型都要有上下文长度：能从 Agent 底座的内置模型目录查到就自动填，查不到由创作者填。

- 图片模型只接 OpenAI 兼容的图片接口（含火山方舟 Seedream），可以填自定义地址。配置含接口地址、模型名、API Key、同时出图数（默认 8）、生图失败重试次数（默认 3，用完用占位图并标“需要处理”）、生图质量（高 / 中 / 低，默认高）、原生长边上限（档位 1536 / 2048 / 2560 / 2816 / 3840，默认 1536；超出部分由本地放大）、后处理（关 / 放大降噪 / 双重放大降噪，默认放大降噪）与放大档位（动漫 `realesrgan-x4plus-anime`（默认）/ 快速 `realesr-animevideov3-x4`，注明「低性能机用，画质下降」/ 保留细节 `4x-NMKD-YandereNeo`，注明「少改原画，保留纹理细节」）。用户不声明接口能力；制作时用到编辑、透明底或某个尺寸而接口不支持，不重试，整部作品暂停并报错，改好设置或换模型后继续（见[视觉管线](./visuals.md) 3.2）。Gemini 兼容接口可以填，但不能编辑、不能出透明底；Seedream 只有 5.5 能画全部素材。
- 文本模型填接口格式（OpenAI Chat Completions、OpenAI Responses、Anthropic Messages）、接口地址、模型名、上下文长度和 API Key，另有一个“兼容哪家”下拉（自动 / OpenAI / DeepSeek / 通义千问 / 智谱 / OpenRouter / 兼容 Anthropic）：自定义地址时把对应的推理参数格式和缓存标记格式写进 Agent 底座的模型 compat，否则“关掉推理”和显式缓存标记在这类服务上会静默失效。文本调用通过 Agent 底座发出，不限并发，制作的并发来自角色分工和出图队列。
- API Key 简单加密后存在应用的配置文件里，方便备份和迁移。

用量统计面板按作品、阶段、模型和时间（天 / 月）统计，每条记录含输入、输出和缓存读 / 写的 token 数，能拿到单价时显示参考金额。统计结果只作参考，不设预算，不做开工前估算，也不会自动停止。参考量级见 `.workflow/decisions.md` 与 `.workflow/evidence/`。

## 7. 编辑器背后的修改

创作者可以在编辑器中修改已生成的内容（界面与交互见 [界面与流程](./ux.md)）：

- 直接修改台词和旁白，或替换角色表情。
- 让 Agent 重写单个场景：一条后端工作流，两个入口。从编辑器发起，结果以差异列表展示，勾选后再应用；从对话面板发起，先出确认卡，确认后重写的结果仍以差异列表确认。
- 原文对照显示当前场景对应的原文段落，原文和场景可以双向跳转；选中一段原文可以直接让 Agent 按它改。
- 单张图重新生成，默认出一张直接替换，也可以手动要求多出几张来挑。
- 把修改存为规则。

修改立即生效，可以撤销，有修改历史。逐条调整演出的时间线编辑器以后再做。
